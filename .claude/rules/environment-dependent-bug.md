# 환경 의존 결함 룰 (Environment-Dependent Bug)

> **근거**: 2026-08-20 postmortem — claude.ai 첨부는 「탭 포커스」 라는 조작자 행동이 성공 여부를 결정. "같은 입력 → 같은 출력" 가정으로 6가설 헛짚음. 수석의 「이게 내가 익스플로러 포커스를 해야 전송이 되는구나」 한 문장으로 해결.
> **이유**: 시스템 안 (코드·용량·형식) 만 조사하고 시스템 밖 (조작자 행동·환경 상태) 을 안 보면 환경 의존 결함은 영원히 숨는다.

## 절대 룰

**"같은 입력 → 같은 출력" 가정 못 하는 결함 = 환경 의존.** 조작자 행동·환경 상태를 조사 변수에 넣어라.

## 정의

**환경 의존 결함**: 코드는 같은데 실행 결과가 다른 결함.
변수는 시스템 밖에 있다. (조작자 행동 · 브라우저 상태 · OS 상태 · 시간 · 다른 세션 · 네트워크)

## 성공 조건이 「사람이 보고 있을 때」였다 (원본 사례)

| 시각 | 상황 | 결과 |
|---|---|---|
| 사용자가 화면 보는 중 | 성공 | ← 탭 포커스 유지 |
| 백그라운드 스크립트 실행 중 | 실패 | ← 탭 unfocused |

이런 결함은 「같은 입력 → 같은 출력」 을 가정하는 모든 조사를 무력화한다.

## 감지 신호 (환경 의존 의심)

| 신호 | 왜 환경 의존 |
|---|---|
| **간헐적** (sometimes works) | 코드 결함이면 항상 동작 재현 가능 |
| **테스터 별 결과 다름** | 다른 조작자 = 다른 행동 |
| **자동 실행 시만 실패, 수동 실행 시 성공** | 사용자가 옆에 있는 것이 변수 |
| **재기동 후 처음만 성공, 이후 실패** | 세션·상태 누적이 변수 |
| **로컬 됨, CI 안 됨** | 환경 (브라우저 UI·display·권한) 차이 |
| **오후만 실패** | 다른 프로세스·리소스 경합 시간대 |

★ 위 신호 하나라도 있으면 → **시스템 밖 변수 조사 우선**

## 실패 만든 결함 vs 못 막은 결함 (구분 필수)

원본 사례:
- **실패 만든**: 탭 unfocused 시 File 업로드 안 됨 (환경 의존)
- **못 막은**: 게이트가 «누적 vs 증분» 비교로 실패를 통과시킴 (설계 결함)

**둘을 구분해야 원인 규명이 엉키지 않는다.**

| 구분 | 특성 | 처방 방향 |
|---|---|---|
| 실패 만든 | 결함 없으면 실패 자체가 없음 | 근본 원인 fix |
| 못 막은 | 결함이 있어도 원래 잡혀야 함 | 검증 게이트 강화 |

동시에 존재하면 둘 다 fix. **하지만 조사에서 섞으면 원인 규명이 늦어진다.**

## 조사 매트릭스 (환경 의존 의심 시)

시스템 밖 변수 후보:

| 카테고리 | 조사 방법 |
|---|---|
| **조작자 행동** | 사용자 로그 (마우스·키보드 활동) · 시각 관찰 · 인터뷰 |
| **브라우저 상태** | 탭 포커스 (`document.hasFocus()`) · 가시성 (`document.visibilityState`) · 사용자 gesture 스택 |
| **OS 상태** | 활성 창 · 절전 · Do Not Disturb · display 절전 |
| **시간·순서** | 재기동 후 N번째 · 다른 세션 진행 여부 · 시간대 |
| **다른 세션** | 같은 브라우저 다른 탭 · 같은 시스템 다른 프로세스 |
| **권한·설정** | 알림·백그라운드 실행·확장 활성화·자동 사용 |

## 처방 원칙 (환경 의존 확인 후)

1. **조작자 개입 최소화** — 확장이 스스로 탭·창 활성화 (사용자 보정 불필요)
2. **환경 상태 계측** — `focus`·`visibilityState` 를 진단에 항상 병기
3. **조건 명시** — 성공 조건 문서화 (예: "탭 포커스 유지 필요")
4. **자동 감지** — 조건 불만족 시 사전 차단 or 자동 복구

## 위반 패턴 (안티)

| 패턴 | 위반 |
|---|---|
| "코드 같으니 결과 같아야" | 환경 변수 무시 |
| 간헐적 실패에 재현 조건만 찾음 | 조작자 행동 안 봄 |
| 6가설 다 시스템 안에서 세움 | 시스템 밖 안 봄 |
| 실패 만든 결함과 못 막은 결함 섞음 | 조사 엉킴 |
| "테스터가 잘못 실행함" 이라는 결론 | 조작자 행동을 결함으로 편입 안 함 |
