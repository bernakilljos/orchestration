# 첨부가 안 되던 이야기 — 원인 규명 실패의 해부 (2026-08-20)

> **대상 독자**: 이 저장소에서 일하는 다음 사람(사람이든 에이전트든).
> **주제**: claude.ai 이미지 첨부가 「처음엔 되고 이후엔 안 되던」 문제를 6번 헛짚은 기록과 그 기제.
> **이 문서의 값**: «고쳤다»가 아니라 **«왜 그렇게 오래 못 찾았나»** 에 있다.
> 결함 자체는 한 줄이었다. 못 찾은 이유가 여러 겹이었다.

---

## 0. 결론부터 — 진짜 원인

`claude.ai` 의 붙여넣기 업로드는 **배경 탭에서 동작하지 않는다.**
브라우저 탭이 포커스돼 있어야 File 업로드가 시작된다.

찾은 사람: **수석**. 한 문장이었다.

> 「이게 내가 익스플로러 포커스를 해야 전송이 되는구나」

그 순간까지 나 (에이전트) 는 **6개의 가설** 을 세워 전부 틀렸다.

---

## 1. 내가 틀린 6가지 — 순서대로

| # | 가설 | 왜 그럴듯했나 | 어떻게 기각됐나 |
|---|---|---|---|
| 1 | 용량 초과 | 553KB 를 보냈다 | 압축해도 실패. 나중에 실측하니 실패 건이 더 작았다 (134KB vs 성공 230KB) |
| 2 | 형식 문제 (PNG) | JPEG 로 바꿔 봤다 | 성공 건도 JPEG 였다 |
| 3 | 장수 문제 (2장) | 1장씩 보내 봤다 | 성공 건도 2장이었다 |
| 4 | 코드 결함 | `content.js` 를 계속 고쳤다 | 이력을 세니 0819 에 여러 건 성공했다 — 코드는 원래 동작했다 |
| 5 | 리로드 누락 | 실제로 낡은 빌드였다 (사실) | 리로드 후에도 실패 |
| 6 | 긴 대화창 | 같은 대화에 계속 보냈다 | 대화 길이는 상관없었다 |

★ ①②③ 은 한 번의 이력 조회로 동시에 기각됐다. **그 조회를 나는 마지막에 했다.**

---

## 2. 기제 — 왜 이 결함이 이렇게 잘 숨었나

### 2-1. 성공 조건이 「사람이 보고 있을 때」였다

| 시각 | 상황 | 결과 |
|---|---|---|
| 0819 17:40·17:43 | 수석이 화면을 보고 계셨다 | 성공 |
| 0820 08:34 | 같음 | 성공 |
| 0820 11:21·11:56·12:58 | 내가 서버 재기동·검사를 돌리는 동안 | 실패 |
| 0820 13:09 | 수석이 브라우저를 보고 계셨다 | 성공 (「보임」) |

★ 즉 **테스트하는 사람의 행동이 결과를 바꿨다.** 이런 결함은
「같은 입력 → 같은 출력」을 가정하는 모든 조사를 무력화한다.

### 2-2. 관측이 정확했는데도 결론을 못 냈다

계측이 이렇게 말하고 있었다:

```text
요청 2장 · File 2 · 이벤트 O · 신규썸네일 0(기준선 2)
```

이 줄은 정답을 담고 있었다 — 「우리는 다 했고 상대가 처리하지 않았다」.
나는 여기서 «상대가 안 받는다» 까지만 읽고 «왜 안 받나» 를 안 물었다.

★ 교훈: **관측을 얻은 뒤에 한 번 더 물어야 한다.**
「A 가 아니다」 는 결론이 아니라 다음 질문의 시작이다.

---

## 3. 계측 자체의 결함 2건 — 같은 계열

원인을 못 찾은 더 깊은 이유는 **계측이 두 번 침묵했다** 는 것이다.

### 3-1. 계측이 「가장 느린 단계 뒤」에 있었다

```js
const [out] = await chrome.scripting.executeScript({ ... __icmAskWeb ... });
//   ↑ 이 함수는 내부에서 waitDone() 으로 답변을 수 분간 기다린다
await report('paste-diag', ...);   // ← 그래서 이 줄이 수 분 뒤에나 돈다
```

첨부는 이미 끝났는데 진단은 «답이 오거나 타임아웃될 때까지» 안 올라왔다.
→ 로그 0건. 나는 그것을 「계측이 안 실렸다」로 오독했다.

**처방**: content 가 붙인 직후 `chrome.runtime.sendMessage` 로 즉시 보고.
기존 경로는 폴백으로 남긴다.

### 3-2. 계측이 재기동에 날아갔다

진단이 메모리 (`_diag[2]`) 에만 있었다. 그리고
`stop_all.bat` → `kill_venv_python.bat` 은 `.venv` python 전부를 죽이는데
relay 도 같은 venv 다. 3서버 재기동을 3회 하면서 진단을 3번 잃었다.

**처방**: `docs/ask_web/diag.log` 에 append.

### 3-3. 두 건의 공통 문장

> **장치를 만든 것과 그 장치가 필요할 때 말하는 것은 다른 명제다.**

- 3-1 = 필요한 시점에 말하지 못했다
- 3-2 = 필요한 때까지 남아 있지 않았다

계측을 넣고 「이제 원인이 보인다」고 보고했는데, 그 보고가 두 번 성립하지 않았다.

## 4. 게이트가 실패를 「통과」시켰다 — 별개 결함

첨부 확인 게이트가 이랬다:

```js
_thumbs = document.querySelectorAll('...figure img, img[alt*="image"]...').length;
if (_thumbs >= _n) break;      // _n = 이번에 붙일 장수
...
if (!_thumbs) return ERR(...)  // ← 지난 이미지가 있으면 영원히 거짓
```

`querySelectorAll` 은 문서 전체를 센다. 같은 대화에 계속 보내니
지난 턴 이미지가 함께 잡힌다. 그런데 비교 대상은 «이번에 붙일 장수» 였다.

| 턴 | 지난 | 요청 | 실제 붙음 | `_thumbs` | 옛 판정 |
|---|---|---|---|---|---|
| 1 | 0 | 2 | 2 | 2 | 통과 ✔ (지난 게 0이라 우연히 맞음) |
| 2 | 2 | 2 | 0 | 2 | 통과 ← 실패인데 |

★ 누적값과 증분값을 비교한 것이다. 1턴만 우연히 정확했다.
→ 기준선을 미리 찍고 증분으로 판정하도록 수정. 시드 7/7 (오탐 3 제거 · 검출력 유지 3 확인).

★ 이것은 「실패를 만든」 결함이 아니라 「실패를 막지 못한」 결함이다.
**둘을 구분해야 원인 규명이 엉키지 않는다.**

## 5. 조사 방법에서 배운 것

### 5-1. 이력을 먼저 세라

`docs/ask_web/*.json` 12건을 세는 데 1분이 걸렸고, 그것이 가설 3개를
동시에 기각했다. 나는 그 조회를 마지막에 했다.

> **재현 가능한 기록이 있으면 가설보다 그것을 먼저 읽는다.**

### 5-2. 이미 실물에 닿아 있는 채널을 써라

claude.ai DOM 을 조사하려고 Playwright 로 새 창을 띄웠다 → 재인증 요구로 실패.
수석 지적: 「또 열면 인증 또 해야하는데」.
확장은 이미 그 탭에 붙어 있었다. 조사도 확장이 해야 했다 (`dom-probe` 확장).

> **새 채널을 만들기 전에, 실물에 이미 닿아 있는 채널을 찾는다.**

### 5-3. 코드 읽기로 단정하지 마라

`new ClipboardEvent('paste', {clipboardData: dt})` 가 Chromium 에서 무시된다고
의심했다. 브라우저에서 직접 재보니 파일이 정상 실렸다 (1개 확인). 가설 기각.

> **30초짜리 실측이 30분짜리 추론을 이긴다.**

## 6. 사람이 이긴 지점 — 기록해 둘 값

수석이 낸 두 문장이 각각 방향을 바꿨다.

① 「claude web 은 처음에는 되었어!!! 그렇다는건 되는거맞자나 그치?」
→ 나는 코드 결함을 파고 있었다. 이 말로 «코드는 된다, 조건이 다르다» 로 전환됐다.

② 「이게 내가 익스플로러 포커스를 해야 전송이 되는구나」
→ 6개 가설이 설명 못 한 것을 한 번에 설명했다.

★ 공통점: **둘 다 «내가 무엇을 했을 때 됐나» 를 관찰한 것이다.**
나는 시스템 안 (코드·용량·형식) 만 봤고, 수석은 시스템 밖 (사람의 행동) 을 봤다.

> **환경 의존 결함은 «조작자의 행동» 이 변수다. 그 변수를 조사 대상에 넣어야 한다.**

## 7. 최종 처방 (구현됨)

| # | 무엇 | 어디 |
|---|---|---|
| 1 | 첨부 시 확장이 탭·창을 스스로 활성화, 끝나면 원래대로 복귀 | `background.js` |
| 2 | 진단에 `focus`·`visibilityState` 병기 → 재발을 로그 한 줄로 판별 | `content.js` + `background.js` |
| 3 | 진단 즉시 보고 (답변 대기 앞으로) | `content.js` → `background.js` |
| 4 | 진단 파일 기록 (`docs/ask_web/diag.log`) | `ask_web_relay.py` |
| 5 | 썸네일 판정 증분화 (누적 비교 제거) | `content.js` |
| 6 | 빌드 토큰 도출화 + manifest 버전 자동 증가 | `stamp_ext_build.py` |

★ 6이 필요한 이유: 토큰이 손으로 적힌 상수라 낡은 코드가 최신 토큰을 보고할 수 있었다.
실제로 두 커밋 낡은 빌드가 돌고 있었다. 이제 파일 내용에서 도출한다.

**검증**: 로직 10/10 · 게이트 시드 7/7 · `--img` 파싱 5/5 · JS 문법 통과.
**남은 것**: 실제 배경 탭 발송 성공 여부는 브라우저 리로드 후에만 확인된다
(확장 관리 UI 조작이라 코드로 불가).

## 8. 한 줄로 남길 것들

- **관측을 얻으면 한 번 더 물어라** — 「A 가 아니다」 는 다음 질문의 시작이다.
- **장치를 만든 것 ≠ 장치가 말하는 것** — 시점과 보존을 함께 봐야 한다.
- **누적과 증분을 비교하지 마라** — 첫 회만 우연히 맞는다.
- **기록이 있으면 가설보다 먼저 읽어라** — 1분이 3시간을 줄인다.
- **실물에 닿은 채널을 먼저 찾아라** — 새 채널은 새 문제를 만든다.
- **환경 의존 결함은 조작자의 행동이 변수다** — 시스템 밖을 봐야 한다.
- **실패를 만든 결함과 막지 못한 결함을 구분하라.**
