PART 01 · WHY 03 / 12

왜 별도 TEAM 빌드인가

본판은 작성자 working repo · 팀에 그대로 배포할 수 없는 4가지 이유

REASON 01
시크릿 노출 방지
본판에는 작성자의 GitHub PAT 가 하드코딩 (fallback). setup/modules/07-github.bat + docs/ini/github.ini. 그대로 팀 배포 시 토큰 유출. TEAM 빌드는 모두 제거.
REASON 02
개인 작업 흔적 제거
본판은 작성자의 state DB · 진행 중인 task · 학습 데이터 포함. 팀원이 받으면 혼란. TEAM 은 state/ · tasks/done/ · learning/ · outputs/ 모두 제외.
REASON 03
설치 진입 장벽 제거
기존 설치는 토큰 필수 가정. 처음 받은 사람이 토큰 발급받아야 → 진행 안 됨. TEAM 은 토큰 입력 prompt + Enter 만 치면 SKIP. 설치 자체는 항상 성공.
REASON 04
독립 git 이력
본판은 작성자의 전체 commit 이력 + remote. 팀에 줄 때 독립적인 첫 commit 필요. TEAM 은 새 git init + Initial commit 1개로 시작.
한 줄 요약: 본판 = 작성자 working · TEAM = 팀에 배포 가능한 클린 출고본
