#01 최상

MicroProcess-Risk Miner

Process Mining + Process Intelligence

왜 중요한가: ERP·결재·카드·출입 로그로 실제 업무흐름을 복원해서 정상 프로세스와 다른 위험 경로를 찾는다.

쉽게 말하면: 회사 업무를 CCTV처럼 보는 게 아니라, 시스템 로그로 '업무 동선 지도'를 그리는 기술.

어떻게 만들까?
  1. ERP/그룹웨어/법인카드/출입 로그에서 case_id, activity, timestamp를 표준화한다.
  2. 정상 프로세스 모델: 품의→승인→결제→증빙→ERP 반영 순서를 만든다.
  3. 실제 로그와 정상 모델을 비교해 사후승인, 우회승인, 반복수정, 누락증빙을 찾는다.
  4. 처음 PoC는 '법인카드+ERP+결재' 3개 데이터만 연결해도 된다.
PoC: 3개월 PoC 가능 난이도: 중
#02 최상

MicroRisk-Twin

Digital Twin / Process Twin / Risk Twin

왜 중요한가: 회사 업무흐름을 가상 복제해서 '이대로 가면 어떤 사고가 날지' 미리 돌려본다.

쉽게 말하면: 실제 회사 업무를 게임 시뮬레이션처럼 복제해서 위험상황을 테스트하는 것.

어떻게 만들까?
  1. 업무 프로세스, 승인권한, 금액한도, 시간규칙을 Twin 모델로 만든다.
  2. 위험 조건: 야간접속, 사후승인, 출입불일치, 거래처 반복을 시나리오로 입력한다.
  3. 시뮬레이션을 돌려 위험점수와 영향도를 계산한다.
  4. 감사팀에는 '조사 우선순위 TOP 50'으로 보여준다.
PoC: 6개월 PoC 가능 난이도: 중상
#03 최상

MicroSynthetic-Risk Lab

Synthetic Data + Risk Scenario Generator

왜 중요한가: 실제 부정/통제미비 데이터가 부족하거나 민감할 때, 가짜지만 현실적인 위험데이터를 만들어 모델을 훈련한다.

쉽게 말하면: 실제 사고가 없어도 '가짜 사고 데이터'를 만들어 탐지훈련을 하는 실험실.

어떻게 만들까?
  1. 정상 거래 패턴을 먼저 학습한다.
  2. 분할결제, 출입불일치, 야간 ERP, 반복 거래처 같은 위험 템플릿을 만든다.
  3. 정상 95%, 위험 5% 비율로 합성 로그를 생성한다.
  4. 탐지모델 성능을 사전검증하고 고객 PoC 데모 데이터로도 쓴다.
PoC: 1~2개월 PoC 가능 난이도: 중
#04 최상

MicroTemporal-Risk Graph

Temporal Graph AI

왜 중요한가: 사람·승인자·거래처·시스템·시간의 관계를 그래프로 묶고, 시간순 위험패턴을 탐지한다.

쉽게 말하면: 누가 누구와 언제 어떤 돈/승인/접속으로 연결됐는지 시간표가 붙은 관계도를 만든다.

어떻게 만들까?
  1. 노드: 직원, 승인자, 거래처, 카드, 계정, 시스템.
  2. 엣지: 결제, 승인, 접속, 출입, 수정, 전송.
  3. 시간속성: 이벤트 발생시각, 간격, 반복주기.
  4. Temporal GNN 또는 규칙+그래프 점수로 위험 관계를 계산한다.
PoC: 3~4개월 PoC 가능 난이도: 중상
#05 매우 높음

MicroEvent-Risk Stream

Real-time Event Stream Intelligence

왜 중요한가: 출입→결제→ERP→승인 이벤트가 발생하는 즉시 위험점수를 갱신한다.

쉽게 말하면: 나중에 보고서로 보는 게 아니라, 위험 이벤트가 생길 때마다 실시간으로 알림을 주는 것.

어떻게 만들까?
  1. Kafka/Flink 같은 스트림 파이프라인을 구성한다.
  2. 카드, 출입, ERP 로그를 이벤트로 변환한다.
  3. 10분/1시간/1일 단위 시간창으로 위험패턴을 계산한다.
  4. 위험점수 임계값을 넘으면 감사/준법 담당자에게 알림을 보낸다.
PoC: 3개월 PoC 가능 난이도: 중
#06 최상

MicroQuantum-Risk Optimizer

Quantum-inspired Optimization / QUBO

왜 중요한가: 수많은 위험 후보 중 가장 의심스러운 조합을 빠르게 고르는 최적화 엔진.

쉽게 말하면: 수천 개 의심 사건 중 '가장 먼저 조사할 50개'를 뽑는 두뇌.

어떻게 만들까?
  1. 각 이벤트를 변수로 만들고, 위험조건을 가중치로 정의한다.
  2. QUBO 형태로 바꿔 조합 최적화 문제를 만든다.
  3. 처음엔 실제 양자컴퓨터가 아니라 simulated annealing, quantum-inspired solver로 시작한다.
  4. 나중에 IBM Quantum/Azure Quantum 같은 하이브리드 실험으로 확장한다.
PoC: 4~6개월 PoC 가능 난이도: 상
#07 높음

MicroCausal-Risk Analyzer

Causal AI

왜 중요한가: 단순히 이상하다고 말하는 게 아니라 '왜 위험해졌는지' 원인을 추정한다.

쉽게 말하면: 위험 점수의 이유를 설명해주는 인과관계 분석기.

어떻게 만들까?
  1. 위험결과와 후보 원인: 야간, 금액, 승인자, 거래처, 월말, 부서 등을 정의한다.
  2. DAG/causal graph를 설계한다.
  3. 개입 시뮬레이션: 승인자를 바꾸면 위험이 줄어드는지 계산한다.
  4. 경영진 보고에는 '원인 TOP 5'로 보여준다.
PoC: 6개월 PoC 가능 난이도: 상
#08 매우 높음

MicroCCM-AI

Continuous Controls Monitoring

왜 중요한가: 분기/연말에 몰아서 감사하지 않고, 통제가 매일 작동하는지 자동 점검한다.

쉽게 말하면: 내부회계 통제를 매일 자동 건강검진하는 시스템.

어떻게 만들까?
  1. RCM 통제활동을 데이터 규칙으로 변환한다.
  2. 권한, 승인, 전표, 증빙, 변경로그를 매일 수집한다.
  3. 미작동 통제와 예외건을 자동 분류한다.
  4. 분기 운영효과성 평가 초안을 자동 생성한다.
PoC: 2~3개월 PoC 가능 난이도: 중
#09 매우 높음

MicroAgent-Control Plane

AgentOps + MCP Governance

왜 중요한가: AI Agent, MCP, RPA Bot이 기업 시스템에서 무슨 일을 했는지 통제한다.

쉽게 말하면: AI 직원들의 출입증, 업무기록, 권한, 사고방지 장치.

어떻게 만들까?
  1. Agent Registry: 모든 Agent/Bot/MCP 서버를 등록한다.
  2. Policy: 어떤 도구를 어떤 조건에서 호출할 수 있는지 정의한다.
  3. Telemetry: tool call, 파일접근, 메일접근, 코드수정 로그를 남긴다.
  4. Kill Switch: 위험행동 감지 시 Agent 실행을 중단한다.
PoC: 2~3개월 PoC 가능 난이도: 중상

MicroEvidence-Ledger

Digital Provenance / Evidence Ledger

쉽게 말하면: 감사 대응용 블랙박스. AI 판단근거를 나중에 증명할 수 있게 저장.

어떻게 만들까?

  2. 중요 판단마다 evidence_id를 생성한다.
  3. 증빙파일과 연결하고 변경이력을 남긴다.
  4. 감사인 요청 시 판단근거 패키지를 출력한다.

Post-Quantum Cryptography / Crypto Agility

4. 6개월 PoC 실행안

1단계: 데이터 연결

입력 데이터: - 법인카드 승인내역 - ERP 전표/수정 로그 - 전자결재 품의/승인 로그 - 출입기록 - RPA/Agent 실행 로그 공통키: employee_id, vendor_id, amount, timestamp, system_id, approval_id

2단계: 위험 엔진
