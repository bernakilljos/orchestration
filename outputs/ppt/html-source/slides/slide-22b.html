01
반복 개발
작게 시작 → 확인 → 확장. 빅뱅 금지. 드라이런 활용.

명확한 Git 흐름
feat/fix/docs 접두사 · PR 단위 작게 · 커밋 전 검증.
03
모듈식 설계
단일 책임 · 느슨한 결합 · 공통은 rules/ 로.
04
정기 감사
주 1회 sync 점검 · 월 1회 CLAUDE.md 갱신 · 분기 1회 로드맵 리뷰.
05
Extended Thinking
복잡 결정엔 긴 추론 모드 · 단순 작업엔 빠른 모드 (Sonnet).

CLAUDE.md 작성

DO

  • 500줄 이하
  • 참조 중심 (rules/* 분리)
  • 구체적 예시 포함
  • 월간 업데이트

DON'T

  • "clean code" 같은 모호함
  • 전체 코드 복붙
  • 중복 (rules/ 와 겹침)
  • 설치 후 방치

자동화

DO

  • hooks 로 강제 (포맷·테스트)
  • !·@·# 단축
  • Sub-Agent 병렬
  • 비밀은 .env

DON'T

  • 메모리만 의존
  • 매번 같은 지시 반복
  • 큰 작업 한 세션
  • 키 하드코딩
