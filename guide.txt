  [3 가지 모드] — 라디오 버튼 또는 인자로 선택
    ⦿ Full Orchestration   Claude + Codex + Gemini (추천)
    ○ Codex 단독           Claude 없이 Codex 만 사용
    ○ Gemini 단독          Claude 없이 Gemini 만 사용

  [방법 A] setup.exe — GUI 위자드 (추천)
    1. https://github.com/bernakilljos/orchestration/releases
    2. OrchestrationKit-Setup.exe 다운로드
    3. 더블클릭 → 위자드에서 모드 라디오 선택 → 경로 → 설치
    4. 완료 후 모드별 자동 실행 옵션 (Claude / codex-go / gemini-go)

  [방법 B] git clone — CLI 인자로 모드 지정
    git clone https://github.com/bernakilljos/orchestration.git
    cd orchestration
    setup\setup.bat        C:\work\myproject       ← Full (기본)
    setup\setup.bat full   C:\work\myproject       ← Full (명시)
    setup\setup.bat codex  C:\work\myproject       ← Codex 단독
    setup\setup.bat gemini C:\work\myproject       ← Gemini 단독
    setup\setup.bat anl    C:\work\myproject       ← Full + 소스 분석

    또는 install.bat 직접:
      install.bat              C:\work\myproject  ← Full
      install.bat codex        C:\work\myproject  ← Codex 단독
      install.bat gemini       C:\work\myproject  ← Gemini 단독

  [방법 C] 사일런트 — 자동화/스크립트용
    OrchestrationKit-Setup.exe /VERYSILENT /DIR="C:\work\myproject"
    OrchestrationKit-Setup.exe /VERYSILENT /TYPE="codex_only"  /DIR="..."
    OrchestrationKit-Setup.exe /VERYSILENT /TYPE="gemini_only" /DIR="..."

  [방법 D] 독립형 설치 스크립트 (v1) — git 저장소에서 직접
    Codex 단독:  install_codex.bat C:\work\myproject
    Gemini 단독: install_gemini.bat C:\work\myproject
    → .env.example 자동 생성, 토큰 로그 기능, 상세 가이드 포함
    → install_codex/gemini.bat 는 PowerShell wrapper (한글 깨짐 방지)

  [방법 E] Team 동기화 (인프라 본체 → 팀 폴더)
    bash .claude/scripts/sync-to-team.sh
    또는 슬래시: /sync-team
    → orchestration_v1 → ../orchestration_v1_team 자동 복사
    → 시크릿 (docs/ini/), 상태 (.claude/state/), 락 제외

  [모드별 사용 흐름]
    Full   →  cd <target>  →  claude
    Codex  →  cd <target>  →  codex-go "회원가입 페이지 만들어줘"
    Gemini →  cd <target>  →  gemini-go "이 코드 검증해줘"

    "사용자가 확인해 주세요" 떠넘김 금지. AI 가 직접 자동 smoke test:
      SQL → 영향 endpoint grep → curl 호출 + 응답 검사
      Controller → endpoint curl + null·NPE·status 점검
      프론트 → Playwright headless render + console.error 잡기
    NPE 같은 NULL+null-unsafe 패턴은 smoke test 한 번이면 잡힘.
    사용자는 최종 시각 확인만, AI 가 기능·화면 검증 책임.
    도구: .claude/scripts/smoke-test-screen.sh
    hook: .claude/hooks/auto-smoke-test.sh (PostToolUse Edit/Write 자동)

  [룰·메모리 빠른 검색 (CLAUDE.md § 7 직후)]
    누적된 룰·메모리·스크립트·hook → grep 비효율 → 의미 기반 lookup 도구.

  [MCP 토큰 최적화 — Deferred Tools (자동 적용)]
    Claude Code 최신 버전부터 MCP 도구 스키마를 지연 로딩(Lazy Load)함.

    문제:  MCP 서버가 많아지면 매 턴마다 수만 토큰이 컨텍스트에 자동 주입

           - 실제 호출 전 ToolSearch("select:도구이름")로 스키마 fetch
           - 사용하지 않는 도구는 토큰 0 소비

    효과:  매 턴 MCP 토큰 5,000~20,000+ → ~100 (이름만)
           컨텍스트 수명 대폭 연장, API 비용 절감

    * Claude Code에 기본 내장 — 별도 설치/설정 불필요
