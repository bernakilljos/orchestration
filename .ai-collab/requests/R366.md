# R366 — Claude CLI 개발부담 최소화 · 회귀 게이트 병행 관리자 실행 계층 · 100점 실증 완성 후속 지시

## 0. 현재 사용자 최신 지시와 작업 상태
- **R363의 PowerShell 파일 삭제 문제는 사용자가 '해결되었다'고 명시했다.** R363 삭제를 다시 실행하거나 승인 번호를 재요청하지 마라. 기존 R365의 과거 P0 삭제 지시보다 **이 최신 사용자 결과를 우선**한다. 파일 삭제 성공에 대한 별도 실측 증거는 해당 보고서/현행 환경에서 필요한 범위만 확인하고, 확인되지 않으면 '사용자 해결 보고'로 명확히 구분한다.
- Claude CLI의 최신 진행 안내: **'회귀 게이트가 약 17분 남아 있어서, 그동안 관리자 실행 계층(예약 작업 실행기와 설치·요청 스크립트 두 파일)을 구현하겠습니다.'** 이 말은 *진행 계획*이지 완료 증거가 아니다. 경과 시간을 새로 17분으로 가정하거나 게이트를 중복 시작하지 말 것.
- 사용자가 원하는 역할 분리('Claude CLI 개발부담'): **Claude CLI가 구현·테스트·자체 수정·커밋·Push·보고를 직접 수행**, **ChatGPT가 GitHub 소스·보고서와 실제 증거를 독립 검토해 결함을 찾아 요청/리뷰 파일로 피드백**. ChatGPT가 Claude CLI에 막연한 무한 전수조사를 반복시키지 않는다.
- 100점은 자기 채점 100/100 선언이 아니다. 미완료 항목의 증거 기반 종결과 회귀/보안/성능/사용성/실제 문제 해결을 모두 확인하는 목표다.

## 1. 지금 즉시: 진행 중인 회귀 게이트 및 구현 작업 보존 (P0)
1. 현재 실행 중인 회귀 게이트의 **프로세스/작업 ID, 대상 커밋과 시험 범위, 시작·종료 상태, 결과 파일**을 먼저 확인. 살아 있는 시험을 불필요하게 재시작하거나 17분 동안 다른 대형 회귀를 동시에 실행하지 마라.
2. **관리자 실행 계층은 현재 작업 중인 파일과 구현 방식을 유지**하고, 기존 담당 워커/세션과 소유권을 확인해 중복 수정·경쟁 커밋·경쟁 파일 쓰기를 막아라. 사용자가 언급한 '예약 작업 실행기와 설치·요청 스크립트 두 파일'을 현행 코드에서 식별한다. 파일 개수가 실제와 다르면 증거로 정정한다.
3. 게이트가 수행 중인 동안 자원 경합이 낮은 구현·코드 리뷰·소규모 표적 테스트만 진행. Windows 권한/UAC 실제 입력은 사용자가 수행; UI 승인 없이 우회·승인 DB 변경·UAC 끄기 금지.
4. 회귀 게이트 통과 직후까지 기다리기만 하지 말고 **검증 가능한 관리자 실행 계층 구현을 완결**하되, 지나친 병렬 Agent/프로세스 실행으로 CPU/RAM/토큰을 소모하지 마라.

## 2. 관리자 실행 계층의 실제 완성 조건 (P0)
- Windows 작업 스케줄러 최고 권한 실행 등 OS 정식 기능을 사용해 **사용자 최초 승인 이후 사전에 고정·승인된 관리자 작업만** 반복 UAC 없이 호출 가능하게 구현.
- 일반 사용자에 의해 고권한 스크립트·인수·승인 목록·작업 정의가 변경되지 않도록 ACL과 인수/대상 경로 검증을 수행. 상대 경로, 리파스 포인트, 경로 치환, 인수 주입, 동시 실행, 실패 후 잔존 프로세스, 타임아웃과 로그 처리를 검사.
- **범용 임의 명령 고권한 실행기 금지**. 관리자 권한이 필요하지 않은 정상 작업은 관리자 실행기를 거치지 않도록 할 것.
- 설치 및 요청 스크립트는 idempotent(중복 설치 안정), 실행 결과와 Windows 사용자 승인 대기 상태 구분, 실제 `LastTaskResult`와 사후조건 확인, 제거/롤백 절차를 제공해야 함.
- 계획된 '두 파일'이 실제 구현 완료·테스트·운영 연결되었는지 확인. 단지 두 파일을 생성했다는 사실로 완료 처리 금지.
- 사전 승인이 필요한 설치 단계는 실제 사용자 동작 하나만 제시하고 이후 동일 문의 반복 금지.

## 3. 100점 실증 품질 기준 (P1)
기존 R338 '다섯 영역 우선, 자동화·자율 실행 마지막'의 단계 순서를 임의로 바꾸지 말 것. 단, 사용자가 **이미 직접 요청한 현장 관리자 실행 계층 해결**은 별도 P0 작업이므로 진행 중인 작업을 중단하지 않는다.

다음 여섯 축을 **기존 지시/보고/원장 증거로** 판단하고, 기존 미완료를 재등록하거나 임의 점수로 PASS 표시하지 않는다.
1. 아키텍처·확장성: 1인 개인용, 단일 정본, 중복 관리자 실행기·중복 스케줄러·중복 Hook 없음. 다른 솔루션에 복사 전파 가능하되 실제 검증 범위만 인정.
2. 테스트·검증: 위험도 기반 표적→영향 범위→필요 시 전체 게이트 순서. 실제 테스트 수/시간/head/새 실패를 기록. 기존 실행 중 게이트 재실행 금지.
3. 사용자 지시 준수: 목표의 실제 사후조건 증거, 재작업 없는 승인 흐름, DONE/PARTIAL/BLOCKED 정직한 판정.
4. 성능·효율: **Claude CLI 개발부담**에 직접 영향하는 토큰/CPU/RAM/프로세스 수/회귀 실행 시간/중복 Hook·Agent 호출을 관찰 가능한 범위에서 기록. 낭비만 줄이고 필요한 검증을 생략하지 않음.
5. 디자인·사용성: 실제 UI 변경이 있을 때만 실측 캡처 기준. 사용자가 금지한 상태줄 ANSI 고정열 복원 금지.
6. 자동화·자율 실행: 앞의 R338 선행 영역 완료 여부 확인 뒤 기존 Supervisor/승인 상태머신 재사용하여 실행·복구·재개 실증. 무의미한 신규 상주 서비스·프로세스 금지.

**최근 보고서에 남은 실제 항목**:
- R354 PARTIAL: 리뷰 폐루프·남은 [claude] 큐·외부 증거 구분. 기존 완료 사항 반복 금지.
- R359 PARTIAL: Stop 훅 18개 통합, status 전송 서비스 실제 반영 및 MCP 최초 세션 확인. 관리자 실행기 구현과 충돌 없이 큐에서 관리하되 지금 대규모 신규 작업을 시작하지 마라.
- R364/R365: 권한/승인 교착과 사용자 지시 완결 흐름. 같은 기능 중복 구현하지 말고 정본 재사용.

## 4. ChatGPT ↔ Claude CLI 역할 분리 및 개발부담 방지
- Claude CLI는 구현 → 실패 재현/수정 → 최소 필요 시험 → commit/push → 실제 효과 측정 → 보고를 한 번의 작업 루프로 처리.
- ChatGPT는 **GitHub에 푸시된 실제 소스·보고서의 결함만 독립 검토**하고 `.ai-collab/reviews/R366.md` 등 적절한 리뷰로 독립 피드백한다. 자기 검증을 독립 검토로 대체 금지.
- Claude CLI가 ChatGPT 검토를 받기 위해 10~20분 대형 게이트를 매번 재시작하거나 새 R 지시를 기다리는 교착 금지. 검토 대기 중에도 범위 내 독립 작업 진행.
- 보고서는 **한 번의 통합 증거 보고 중심**. 과도한 요약·출력 반복, 전체 로그 본문 복사, 불필요한 파일 생성, 임시 파일 방치 금지. 운영 로그/승인 근거/감사 기록 보존.
- 사용자 지시와 검증 증거가 충돌하면 새 지시를 무시하거나 임의 PASS를 만들지 말고 원인을 짧게 명시하고 안전하게 조치.
