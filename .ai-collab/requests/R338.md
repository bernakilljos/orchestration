# R338 — 100점 기준 통합 품질 향상: 5영역 먼저, 자동화·자율 실행은 마지막

## 사용자 결정 (해석을 바꾸지 말 것)
- 이 Orchestration Kit은 **사용자 1명만 쓰는 개인용**이다.
- 사용자가 기존 평가 항목 중 **자동화·자율 실행(15/20)을 제외하라는 뜻이 아니다. 반드시 개선한다. 다만 다른 영역을 전부 먼저 완료한 **마지막 단계**에 수행한다.**
- 목표는 점수 숫자 맞추기가 아니라 실제 개발 품질과 명시적 사용자 지시 준수, 디자인 완성도, 적재적소 검증/에이전트 선택을 증거로 높이는 것이다.
- 이미 등록된 **R334 → R335 → R336 → R337**의 선행 작업을 먼저 처리한다. R338은 해당 결과를 확인해 중복 구현을 하지 않고 빠진 실제 결함만 개선한다. 선행 작업을 중단하지 말 것.

## 단계 1 — 다음 5영역을 우선 개선하고 실제 검증
1. **아키텍처·확장성(기존 잠정 18/20):** 실제 실행 경로에서 상충하는 SoT·과거 강제 위임/정책·중복 규칙을 찾아 최소 수정으로 통일. 개인용을 다중 사용자 인프라로 확장하지 않음.
2. **테스트·검증(18/20):** R334·R336 결과를 점검하여 변경의 위험도에 맞는 단위·통합·영향 범위 회귀·전체 회귀가 상황별로 올바르게 선택되는지 실행 증거 확보. 전체 테스트 무조건 반복도 금지, 품질/안전 게이트 무단 생략도 금지.
3. **사용자 지시 준수(10/15, 최우선):** 사용자 원문이 '모두 끝내고 검증 후 마지막에 한 번 보고'면 하위 1/N 완료 후 보고·Stop하지 말고 잔여 실행 가능한 작업을 끝까지 수행. '하나씩 보고' 또는 별도 지시 없음은 해당 의도대로. Hook·Ledger·Supervisor가 임의로 사용자 지시를 덮어쓰지 않게 R335의 실제 종단 검증.
4. **성능·효율(9/15):** 관련 테스트 반복, Hook 오탐/지연, Agent 시작·취합 및 중복 읽기, 모델 비용에서 **실제 낭비만** 줄임. 철저한 검증에 쓰는 필요한 시간은 결함으로 취급하지 않음. ChatGPT 협업을 위해 임시로 돌렸던 5분 cron 397회는 **평시 일반 개발 오버헤드 통계에서 제외**하고 별도 구분.
5. **디자인·사용성(8/10):** R336을 바탕으로 실제 UI·상태줄 캡처가 있는 범위에 대해 가독성, 정렬, 정보 구조, 반응형·접근성 검증. 기준 JSON·설계 규칙만 보고 시각적 품질 PASS로 단정하지 않음. 사용자가 요청하지 않은 기존 상태줄 고정 ANSI 열 복원이나 화면 변경 금지.
각 단계마다 '원래 문제 → 파일/재현 근거 → 최소 수정 → 수정 전 실패·후 성공 → 회귀 결과 → 실제 사용자 효과'로 검증. 이미 해결된 건 재수정하지 말 것.

## 단계 2 — **마지막에 반드시 자동화·자율 실행도 개선**
선행 5영역이 실제 완료된 다음에만 자동화·자율 실행(기존 잠정 15/20)을 검토·개선한다. **이번 단계는 생략/제외 대상이 아니다.**
- 1인용 시스템에서 명시적 사용자 요청을 종단까지 이어가는 자동 실행·재시도·복구·완료 지속성, Supervisor/상태 원장과 Hook의 간섭 여부 점검.
- 자동화가 사용자 허용 작업(정상 Git push·승인된 화면 검증 등)을 이유 없이 막는 오탐 최소화.
- 자동 재개·작업 연속성은 실환경에서 가능한 부분을 검증하되 세션 종료·승인 대기·실제 장애 같은 구조적 한계를 숨기지 않는다.
- 신규 상주 프로세스·과잉 Agent/Hook/플러그인 설치 없이 기존 자산을 우선 재사용.
- 사용자가 명시적으로 요구한 완료·보고 조건을 우선하고, 승인·보안·데이터 손실·비용처럼 필요한 보호 조치는 그대로 유지한다.

## 작업 순서와 운영 안전
- R334~R337을 **중복 수행하지 말고** 완료·검증 상태/미완료 증거를 살핀 뒤 R338에서 이어받는다.
- 단계 1 다섯 영역을 마친 뒤 단계 2 자동화를 마지막으로 진행한다. 각 영역의 완성도에 대한 추측 점수 올리기를 완료 조건으로 삼지 말 것.
- 미완료가 있으면 억지 PASS로 바꾸지 말고 PARTIAL/BLOCKED 근거와 다음 실행 가능한 항목을 보존한다. 사용자 '전부 완료 후 보고' 지시가 있으면 중간 부분 완료를 최종 완료로 보고하지 말 것.
- 같은 작업·같은 커밋에 대한 중복 보고를 만들지 않고, 완료 승인·head 일치 전에는 보고서 삭제 금지. 운영 DB·원장·회복·감사 기록·진행 중 작업 보존.
- 사용자 별도 승인이 필요한 민감 조치는 원래 승인 정책을 준수. 검증된 코드 수정만 안전하게 commit/push, 최종 보고는 R338 보고서 1개로 게시한다.

## 명확한 인수 기준
**1단계: 아키텍처 → 검증 → 지시 준수 → 성능 → 디자인 개선 완료 및 근거 확인. 2단계: 그다음 자동화·자율 실행 개선까지 진행.** 실제 완료되지 않은 항목을 PASS로 기재하지 않음.
