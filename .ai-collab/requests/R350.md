# R350 — 커밋 직전 누락 발견으로 회귀 게이트를 5~6회 다시 돌리는 낭비 근절

## 사용자 실제 재현
- `plugins/mcp_media/plugin.json` 수정 후 커밋 시 `.claude-plugin/marketplace.json` 동반 변경 요구.
- 두 파일의 mcp_media 버전을 1.0→1.0.1로 맞춘 후 재커밋하자 `regression-gate (stale)` 차단 → 고비용 게이트 재실행.
- 사용자의 핵심 불만: **'1번 할 것을 5~6번 한다. 제대로 검증하자.'** 규칙 무력화가 아니라 사전 영향 조사·순서 개선으로 재실행을 방지하라는 뜻.

## GitHub 코드로 확인된 원인 후보
- `.claude/hooks/pre-commit-full-check.sh`에는 `guide.txt`, CLAUDE.md auto-stats, plugin.json→marketplace.json, 신규 Hook→settings.json, setup→BUILD.md, staged tree/code_tree에 대한 regression-gate stamp 검사가 있다.
- `.claude/scripts/lib/independent_verifier.py`의 `regression_gate` 및 `impact_selection`은 안전성 핵심. 유효하지 않은 게이트를 무시해서 커밋하면 안 된다.
- 현재 코드는 코드 지문이 동일하면 문서-only 변경 때 결과 재사용을 일부 지원하므로 **기존 지원을 재활용**하고, stale의 실제 판정 이유(code_tree·tree·검사 시점·플러그인 메타데이터 변경 등)를 재현 확인하라. 가설을 사실로 보고하지 말 것.

## P0 — 변경 집합 확정 후 검증하는 올바른 계획
1. 수정/커밋을 시작하기 전에 실제 staged/unstaged 파일과 관련 설정·계약을 분석하여 **필요한 동반 변경 파일을 전부 동적으로 발견하는 가벼운 preflight**를 실행. 특정 플러그인·경로·버전 하드코딩 금지. 이미 갖춘 Hook 의존 조건·기존 설치 메타데이터에서 규칙을 재사용하라.
2. 플러그인 manifest와 marketplace 버전/참조, 관련 guide/CLAUDE.md 자동 통계, 설정/배포/동기화/생성 산출물 등 **실제 변경이 필요한 것만** 최종 회귀 전 확정하고 함께 stage한다. 관계없는 변경을 끼워 넣거나 단순 커밋마다 강제 version bump 금지.
3. 수정·문서·메타데이터 작업을 모두 완료한 뒤 최종 staged code fingerprint를 기록. **그 동일한 지문**에 대해 필요한 회귀 검증을 실행하고, 내용이 같다면 커밋에서 재사용. 검사 중 실질 코드가 바뀌면 적절한 검증을 반드시 갱신.
4. PreToolUse/commit Hook이 체크 직전에 파일을 수정하거나 다른 Hook과 중복 확인하여 지문을 바꾸는지 확인. 가능한 자동 생성·동기화는 preflight로 옮기고 최종 Hook은 읽기 전용 검증으로 최소화.
5. 실패 시 사용자가 반복 시도하게 만들지 말고 **한 번에 모든 누락 항목과 정확한 수정 방법을 반환**. 실패 이유는 미스테이지/지문 불일치/회귀 실패/검사 불가/승인 필요로 분리.

## P1 — 느린 검증의 정직한 최적화
- 회귀 검사 재실행을 줄이되 skip·xfail·결과 위조·게이트 우회(`--no-verify`) 금지.
- R336 위험 기반 검증과 R334/R339 캐시·메모리 최적화를 활용. 현재 소스에 영향을 주지 않는 문서/메타데이터 변경은 실제 코드·테스트 커버리지에 영향이 없는지 확인 후 유효한 기존 결과를 재사용.
- JSON·plugin manifest 등 실행 계약 변경에 필요한 schema/semantic checks를 해당 지문으로 분리할 수 있는지 분석하되, 중요 변경을 단순 문서로 오인하여 검사 누락 금지.
- 검증 속도와 실질적인 테스트 탐지력, 시스템 CPU·RAM/반응성, 전체 commit 완료 시간을 함께 측정.

## P2 — 재현·역검증
- 격리 fixture에서 (A) plugin manifest 변경 + marketplace 누락, (B) plugin manifest + marketplace 동시 stage, (C) guide/CLAUDE auto-stats 필요/불필요, (D) 신규 hook + settings, (E) setup/BUILD, (F) 검증 후 진짜 코드 변경, (G) 문서-only 변경, (H) 회귀 실패/승인 필요 및 중간 stage 변경 사례를 테스트. 특정 경로명에만 맞춘 하드코딩이 아니라 메타데이터/의존 관계로 일반화 검증.
- **preflight에서 동반 파일 누락을 한 번에 검출**하고 final heavy regression 실행 후 정상 commit은 재검증 없이 진행되는지 입증. 실제 수정 후 stale은 정상적으로 차단해야 한다.
- 동일 작업을 기존 방식과 새 방식으로 반복 실험하여 사용자 시도 횟수, Hook 차단 횟수, 회귀 게이트 실행 횟수, 전체 wall time, test PASS/실패 탐지와 자원 사용량 보고.
- 코드 변경 없이 규칙 문구만 추가하고 완료 주장 금지. 가장 낮은 위험의 기존 스크립트·Hook 최소 변경을 우선한다.

## 실행·최종 보고
현재 사용자 작업/백그라운드 회귀가 진행 중이면 **중단하거나 현재 스테이지를 임의 변경하지 말고** 그 실행 결과를 기록한 다음 충돌 없이 적용. 사용자의 명시 작업 완료 후 일괄 보고 우선, 1인 운영·보안 저장소 파일 권한 강화 제외, 운영 DB/원장/승인·감사 기록 보존. 관련 공식 Git 및 Git Hooks, pytest 문서 본문을 실제 확인하고 지원 버전과 대조한다.

`.ai-collab/reports/R350.md`에 재현 로그·근본 원인·변경 diff·실측 전후·회귀 및 결함 주입 증거·미검증 항목을 기록하고 실제 commit/push. ChatGPT 재검토에서 누락되면 재지시하되 무의미한 핑퐁 금지.

**핵심 완료 기준: '커밋 시도 → 누락 발견 → stage → 회귀 반복'을 '사전 관계 조사 → 필요한 변경 일괄 stage → 유효한 검증 → 커밋'으로 전환하되 안전 검증은 절대 약화하지 않는다.**
