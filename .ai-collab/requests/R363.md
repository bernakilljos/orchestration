# R363 — 최우선: Windows PowerShell 이름 충돌 파일 제거 작업 마무리

## 사용자의 실제 목표
Windows PowerShell에서 `powershell` 입력 시 '앱 선택' 창이 뜨는 원인으로 조사된 **`C:\Windows\System32\powershell` (확장자 없는 0바이트 객체)**를 안전하게 제거하고 정상 동작을 확인한다. **절대로 정상 `powershell.exe`를 삭제하지 말 것.**

이 파일에 대해 현재 보고된 정보: 0바이트 일반 파일·링크 아님·서명 없음, 별도의 Microsoft 서명 정상 `powershell.exe` 존재, 일반 권한 삭제 실패, Windows 관리자 권한 필요. 이 정보는 직전 CLI 실측 보고에 따른 것이며 실행 직전 대상에 대해 재확인할 것.

## 기존 지시문 교정 — 이 작업의 우선순위
**이 작업에 R363 이전의 12종 시뮬레이션, R364 24종 시뮬레이션, CI 전체 회귀, 프로젝트 전파, 문서 검색을 선행조건으로 걸지 않는다.** 이것들은 별도 안정화 작업이다. 현재 사용자 요청은 시스템 설계 보고서가 아니라 **한 파일의 제거와 결과 확인**이다. 이미 작성한 remove-shadow-command.ps1과 기존 격리 시험 결과를 우선 재사용하고 새 스크립트·새 명령·새 승인 번호를 불필요하게 만들지 않는다.

## 지금 실행할 4단계
1. **대상 최소 재확인**: `C:\Windows\System32\powershell`이 실제 0바이트 일반 파일이고 링크·보호된 시스템 구성요소가 아니라는 기존 검증을 확인한다. 정상 `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`와 구분한다. 경로·유형이 불일치하면 중단하고 정확한 차이만 보고.
2. **기존 승인 요청 확인**: CLI가 마지막으로 보고한 `appr-713617e80d83`의 DB 상태와 기존 고정된 관리자 실행 명령/스크립트 해시를 조회한다. 아직 유효한 동일 범위 대기 승인이라면 **그 번호를 유지**하고 명령을 변경하지 않는다. 이미 승인 완료됐다면 같은 범위에서 1회 실행한다. 만료/달라진 범위인 경우에만 실제 사유를 명시하고 새 요청을 만든다. 사용자의 일반 재촉 문장을 시스템 승인의 위조로 사용하지 않는다.
3. **정상 권한으로 실제 제거**: 내부 승인 및 Windows UAC가 요구되는 경우 정식 절차를 지킨다. 사용자가 필요한 UAC 확인을 한 후 기존에 고정해 둔 검증 스크립트로 조건부 삭제한다. 사용자 승인 없이 Hook/DB를 우회하거나 관리자 권한을 몰래 획득하지 않는다. **권한이 없어서 막힌 경우, 같은 승인 설명을 반복하지 않고 상태를 WAITING_APPROVAL/WAITING_UAC로 한 번만 보고한다.** 다른 작업은 별도로 진행할 수 있지만 이 삭제 작업을 완료한 척하지 않는다.
4. **사후 검증**: 삭제 명령의 종료 코드뿐 아니라 `Test-Path -LiteralPath 'C:\Windows\System32\powershell'`가 False인지, 정상 전체경로 `powershell.exe`가 실행되는지, 원래 이름 기반 실행에서 '앱 선택' 팝업이 재발하지 않는지 검사한다. 실제 파일이 남아 있으면 미완료다.

## 대화 및 작업 제어 지침
- 사용자가 여러 차례 `지워`, `없애`라고 반복하면 **새로운 전수조사와 10~15분 회귀 테스트로 우회하지 말고 이 작업의 현재 실행 단계에 집중**한다.
- 기존 명령이 고정돼 승인 대기 중인데 설명 문구/조사 때문에 새 명령을 만들지 말 것. 현재 번호를 한 번만 짧게 안내하라.
- 위험 승인과 Windows UAC는 사용자가 수행해야 하는 정상 절차다. Claude가 이를 대신 입력·클릭·우회했다는 거짓 보고는 금지한다.
- 명령이 아닌 별도 대안(예: 정상 powershell.exe 전체경로 호출)으로 임시 회피할 수 있어도 **원래 파일 제거 성공으로 바꿔 보고하지 말 것**.
- 사용자에게 정상 완료한 것처럼 말하면서 보고서 작성만 계속하는 행동 금지. 현재 작업 처리와 R364의 구조적 개선은 분리한다.
