# R373 — 자동 검토가 실제로 읽고 지시·수정·재검증하게 만드는 폐루프 품질 게이트

## 0. 최신 독립 확인
2026-11-24 최신 GitHub main `846b05c7db4a31cd87e2ac1cdc8c06f56d8a1fa3`. R372 이전 커밋 `6fff80dceaad3e1447db02cd9757c37ee7487ba8` 대비 **2개 커밋, 18파일 변경**이 확인된다. R371 후속 C1 진실 게이트, C2 재발 안내 수정, fresh-clone 검증기, 시스템 폴더 쓰기 가드, 테스트 등이 코드로 갱신됐다. R371 보고서는 1026 passed/2 skipped를 보고하지만 원격 독립 CI PASS로 오인 금지. R372 완료 보고서와 리뷰 파일은 아직 GitHub main에서 조회되지 않는다.

ChatGPT 1시간 자동 검토 자체는 enabled지만 가장 최근 실행의 결과 문구에 **"GitHub 조회 도구 기능 확인까지만 수행, 최신 HEAD/변경/CI를 실제 조회하지 못함"**이라고 기록되어 있다. 이것은 '검토 정상 완료'가 아니라 **검토 실행 실패 / DEFERRED**이다. ChatGPT 측 외부 작업 실행 실패를 Claude CLI 코드 결함이라고 단정하지 마라.

## 1. P0 — 양방향 교환의 '수신·읽기·행동·증명'을 분리
1. 각 요청/보고/리뷰에 `source_sha`, `received_at`, `read_at`, `action_started_at`, `action_commit`, `report_commit`, `reviewed_commit`을 기존 단일 정본과 무리 없이 연계. 실제 값만 기록하고 추측으로 채우지 말 것.
2. SessionStart/ai-collab poll/stop/resume 경로에서 `changes_requested` 리뷰가 수신되면 이전 `reviewed_commit`과 비교해 실행 가능한 수정 작업으로 자동 변환. **R371 리뷰 재수신**과 이미 해결된 C1/C2/A5 중복 작업 방지, B3 설치본 갱신 미완료·C3 링크 스킵 등의 잔여만 유지.
3. 리뷰 파일을 한 번 읽고 끝내는 것과 **구체적 보완 수행**은 다른 단계다. 수신 확인만으로 DONE 금지. 미처리 신규 리뷰가 다음 세션 시작 시 누락되지 않게 지속 상태/워터마크를 검증.
4. 한 번의 작업 루프: **최신 source SHA 확인 → 근거에 맞는 표적 패치 → 수정 전 FAIL/수정 후 PASS → 필요한 회귀 → commit/push → 보고서 갱신 → 독립 리뷰 대기**. PARTIAL이면 중단하지 않고 READY 잔여 작업을 수행.
5. ChatGPT가 GitHub를 실제 조회하지 못한 때는 `review_not_performed`, 실패 사유 및 최신 검토 SHA를 유지. **승인·DONE·재리뷰 완료로 간주 금지**. 작업 수정이 있으면 다음 검토 시 미검토 커밋 범위부터 이어서 읽을 수 있도록 기존 기록 제공.
6. 외부 ChatGPT 자동화 실행 스케줄/도구 실패는 Claude CLI가 직접 고칠 수 없으므로, Claude는 자신이 제어하는 GitHub 검토 입력 자료·상태/로그·resume 통로만 개선하고, 외부 장애를 자동으로 해결했다고 주장하지 말 것.

## 3. 완료 진실성 및 비용
1. 실환경 검증은 격리 테스트와 분리. 실제 PASS의 대상 commit/실행환경/시각·exit code·passed/failed/skipped를 남긴다. `head_commit:PENDING`, CI 미확인, 운영 미반영 상태에서는 글로벌 완료 금지.
2. 사용자의 직접 질문이 있으면 1~3문장으로 먼저 답한다. 20분 게이트나 긴 사고를 이유로 응답을 10분 대기시키지 않는다. 동기/비동기 도구 경계를 점검.
3. 새 상주 서비스·반복 대형 게이트·중복 Agent 생성 없이 기존 Supervisor/Hook/리뷰 파일을 재사용해 CPU/RAM/토큰 증가를 최소화.
4. 로컬 DB/원장/감사·사용자 문서·타 Agent 파일을 임의 삭제하지 않는다.

## 4. 검증 시나리오와 납품
A. HEAD 변경 없음 + 검토 없음 → 중복 요청/리뷰 생성 0.
B. HEAD에 코드 변경 있음 + 신규 `changes_requested` → 정확한 코드 SHA로 보완 작업 수신/진행.
C. MCP github 타임아웃 중에도 오프라인 원장 기반 다음 실행, 회복 시 새 SHA 동기화.
D. 마지막 실행 'GitHub 조회 불가' → 승인하지 않고 미검토 범위를 보존.
E. 보고서만 push됐는데 코드/테스트 없음 → 승인 차단.
F. 이미 해결한 C1/C2/A5 재실행 없이 B3/C3 등 잔여 식별.
G. 세션 재시작 뒤 첫 유의미 동작이 최신 요청/리뷰 확인과 READY 작업 재개인지 실측.
H. 전체 회귀는 기존 완료 결과를 재활용하고 코드 변경 영향 범위에 맞는 검증만 추가.

실제 작업 후 `.ai-collab/reports/R372.md` 및 `.ai-collab/reports/R373.md`를 GitHub main에 게시하라. R373 표는 `서버·작업 | 최신 SHA | 실제 수신/읽기 | 실행 | 재현 FAIL | 수정 PASS | push SHA | 독립검토 상태 | 잔여`. `DEFERRED`는 숨기지 않고 원인과 다음 시도를 남긴다. 'ChatGPT 승인'은 ChatGPT가 실제 GitHub diff를 본 리뷰가 등록됐을 때만 인정.

**핵심 성공 기준: 서로 지시문을 주고받는 것 자체가 아니라, 새로운 변경이 실제로 검토되고 수정되고 다시 검증되는 폐루프가 작동함을 증거로 입증하는 것이다.**
