# R342 — 실제 고객용 시스템 아키텍처 PPT 45/100: 설명문서에서 전문 기술 시각화로 개선

## 사용자 지시 · 실행 순서
사용자는 Claude CLI가 만든 **ICM AgentGo 1.5 시스템 아키텍처 11장 PPT**를 40/100으로 평가했다. ChatGPT의 파일 실물 검토 평가도 45/100이다. 예전 10점보다 좋아졌으나 80~90점 이상의 개발 문서/PPT 생성 품질이 목표다. **아키텍처, 순서도, 데이터흐름, 배포, 보안 경계, AI 연동을 텍스트 표로만 나열하지 말고 기술적으로 맞는 그림으로 설명할 수 있게 기존 PPT Skill·Command를 근본 보완**하라.

이 요청은 **향후 PPT 제작 능력 개선**에 관한 것이다. 고객 내용의 재작성이나 기존 PPT를 강제로 수정·배포하라는 명령은 아니다. 첨부 원본은 ChatGPT 대화에만 제공됐으며 Claude CLI 로컬 파일 경로를 추측하지 말고, 접근할 수 없으면 아래 관찰 근거를 사용해 스킬·지침과 샘플을 개선한다. 사용자 민감 고객 문서나 원본 PPT를 동의 없이 공개 GitHub에 업로드하지 말 것.

현재 진행 중 R335~R341을 임의로 중단·중복 수행하지 말고 선행 업무 후 처리하라. 지시된 전체 작업과 검증을 마친 뒤 보고하는 사용자 우선 정책 유지.

## 실제 PPT 11장 관찰 결과 (증거)
- 1장 표지 / 2장 SCQA 요약 / 3장 목차 / 4장 품질 목표 / 5장 시스템 컨텍스트 / 6장 11개 내부 구성요소 / 7장 배포 / 8장 데이터 저장 / 9장 보안 / 10장 AI 연동 / 11장 결정사항.
- 장점: 문서 논리·기술 키워드·결론형 제목·출처/관련 문서·서식 일관성은 갖췄다.
- **5장**: 내부회계→9077 게이트웨이→9079 백엔드→외부 AI→9080 RPA→회사 DB를 1~6번 네모/화살표로 잇고 옆에 통신 표를 나열해, 상시 구성 관계와 실제 호출 흐름을 혼동시킬 가능성이 크다. 외부·내부 경계, 선택 서버·회사 DB, 연결 방향, 프로토콜, 필수/선택을 구분한 **C4 Context/Container 다이어그램**이 더 적절하다. 임의의 연결관계를 그리지 말 것.
- **6장**: 규칙·OCR·RAG·AI·판정 기억·RPA 등 11개 구성요소가 목록/설명 표 중심이다. 구성요소 관계·조건부 호출/규칙 선평가·분기·외부 호출 조건을 표현하는 **Component + 필요시 Dynamic/Sequence** 그림이 부족.
- **7장**: 필수 서버 2·선택 서버 2, 설치 형태 4종을 설명하지만 **Deployment/Network zone/Firewall** 그림 부재.
- **8장**: SQLite 기본 + 회사별 MySQL/MSSQL/Oracle 동시 저장과 실패 처리 502를 설명하나 저장소/동기화/실패 경로의 **Data-flow/Storage** 그림 부재.
- **9장**: HMAC/AES/회사별 키/C2PA 방식 봉인/관리자 인증/RPA 인증의 표/카드 설명만으로 **Trust boundary, key scope, ingress/egress** 이해가 어려움.
- **10장**: 사내 AI→Vertex→Azure OpenAI→OpenAI/보조 Gemini/로컬 Ollama·OCR 선택/미설정 동작을 표로 서술. **Provider priority/fallback/조건부 호출** 그림 부족.
- 결과물 pptx 내부 분석: 16:9, 11장, 실제 삽입 picture shape 0. 텍스트·도형은 편집 가능하다는 장점이지만, 그림은 단순 네모/연결선 위주. 단순 picture=0 자체를 품질 결함이라고 판단하지 말고 **의미 있는 다이어그램의 부재**를 문제로 삼을 것.
- 반복 패턴: 표·상세 문장이 본문을 지배해 외부 검토자/고객사가 한눈에 구조를 파악하기 어려움. 문서형 텍스트와 발표용 정보 밀도를 구분.

## P0 — 기존 PPT/Architecture Skill·Command의 실제 결함 추적
- 핵심 경로: `.claude/commands/design_ppt.md`, `.claude/commands/make-ppt.md`, `plugins/design_ppt/commands/arch-auto.md`, `plugins/design_ppt/commands/design_ppt.md`, `plugins/design_ppt/skills/skill-ppt-pitfalls.md`, `plugins/design_ppt/README.md`, `.claude/scripts/verify-ppt-overflow.py` 및 관련 Architect/Designer 에이전트.
- 실제 확인된 문제: `arch-auto.md` 선택지가 mindmap/layered/cheatsheet **3가지에 국한**되어 Context/Container/Component/Deployment/Sequence/DFD/Security diagram에 대응하지 않음. 기존 PPT 'pitfalls'는 잘림·OCR·페이지 번호 등 **기계적 검증 위주**라 구조의 정확성·전문성·아키텍처 의미 검증이 부족.
- `README`는 HTML/CSS→Playwright→PPTX 파이프라인과 자산 생성에 치중하며 실제 기술 다이어그램 의무/선택 기준이 약함. 실제 호출되는 정본이 어느 것인지 확인하고 중복 파일은 호환성 유지하며 SoT 통일.
- 기존 규칙을 덮어쓰거나 별도 중복 Skill/Command/Agent를 무분별하게 추가하지 말고 기존 것을 확장.

## P1 — 문서 유형에 따른 의미 중심 시각화 엔진
1. 사용자 목적(임원 보고/고객 설명/개발자 설계/운영자 설치/보안 검토)과 문서 유형을 먼저 분류. **시스템 아키텍처**면 C4 System Context/Container, 필요한 경우 Component/Deployment/Dynamic/Sequence/DFD/Trust Boundary를 사용자 필요와 실제 콘텐츠에 따라 선택. 모든 슬라이드에 무조건 그림을 넣지는 않는다.
2. **구조(어디에 무엇이 있는가)**와 **처리흐름(언제 무엇을 호출하는가)**, **배포(어느 장비·네트워크 영역인가)**, **데이터(어디에 저장되는가)**를 섞지 않는다. 화살표에는 방향/프로토콜/조건을 넣고 내부/외부/고객사/선택 구성은 시각적으로 구분한다. 도식의 의미를 문서 원본·코드·설정과 교차 검증하고 추측 연결선 금지.
3. 긴 텍스트 테이블이 반복되면 '다이어그램 1개 + 핵심 포인트 + 필요시 상세표/부록'으로 정보 구조 개선. 텍스트 과밀, 작은 글씨, 기계적인 3열 카드, 매 장 같은 박스/요약문구 남용을 줄이고 내용에 맞는 레이아웃(구조도, 시퀀스, 매트릭스, 타임라인, 비교, 의사결정)을 선택.
4. PowerPoint 편집 가능성을 중시: 적절한 native shapes, 선/라벨/텍스트·SVG 등 사용. 전체 페이지를 한 장 그림으로 평면화하지 말 것. Mermaid/PlantUML/Graphviz/Python-pptx/HTML/Playwright 등은 **지원되는 기존 툴과 실제 렌더 결과에 맞게** 선택하고 꼭 필요한 도구만 사용.
5. 색·서체·여백·정렬·컨트라스트·선의 교차·라벨 가독성·한글 폭·작은 화면/프로젝터 시인성을 점검. 꾸미기보다 정보 전달; 아키텍처에서 의미 없는 AI 스타일 네모·그라데이션 반복 지양.
6. 실제 렌더링된 **모든 슬라이드 이미지**로 시각 검증: 잘림·겹침·화살표 잘못 연결·선 방향·다이어그램 논리·내용 누락·한글 폰트, 중요한 표와 링크. OCR만 PASS여도 내용/디자인 품질 PASS로 간주하지 않는다. 파일에서 shape 개수만 세고 완성도 판단 금지.
7. 원본 정보 보존: 포트/서명/DB/AI provider/선택·필수/실패 조건 등 의미를 절대 변경·창작하지 않음. 수정 이력/근거/검증 범위 기록.

## P2 — 재발 방지 및 객관적 품질 게이트
1. 평가 루브릭 총 100점: 구성 논리(20), 정보 정확성(20), 아키텍처 시각화(25), 디자인/가독성(20), 전달력/전문성(15). 기준 샘플 현재 평가 45점, 향후 독립 리뷰 목표 80점 이상. 자체 점수만 올리거나 미확인 PASS 금지.
2. 실제 콘텐츠와 유사하지만 고객 민감정보 없는 **격리된 샘플 아키텍처**로 최소 1세트의 Before/After PPT를 생성·렌더링해 시스템 구성/컴포넌트/배포·보안/데이터/AI 라우팅 중 필요한 그림을 실제 포함. 입력 사실과 화살표/선 연결이 일치하는지 검증.
3. 기존 자동 overflow/정렬/OCR 검증과 신규 의미/디자인 점검을 통합: 가려짐 0, 근거 없는 연결 0, 치명적 기술 오기 0, 내용 누락 0, 읽기 가능, 원본과 구조 의미 일치. 편집 가능 여부와 캡처 검증 여부 기록.
4. 새로운 고비용 API 자산 생성·유료 모델 병렬 벤치마크 사용자 승인 없이 수행 금지. 단순 슬라이드 생성에는 무조건 다중 Agent 호출 금지(R337).
5. 실제 개선된 시각 결과를 근거로 판단할 수 없거나 편집가능 구조가 손상되면 PASS 금지. 사용자 지시 보고 시점 준수. 원본 문서/운영 데이터 손상 금지.
