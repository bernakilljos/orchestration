# R337 — 서브에이전트·멀티에이전트의 상황 적응형 선택과 정책 충돌 제거

## 실행 순서
R334(회귀·wait), R335(사용자 지시 우선), R336(위험도별 검증·디자인)를 먼저 확인·완료한 후 진행. 기존 진행 작업을 중단하거나 같은 변경을 반복하지 않는다. 사용자 '전부 완료 후 보고' 지시가 있는 경우 하위 작업 한 건 완료만으로 최종 보고/Stop하지 않는다.

## 직접 확인된 정책 불일치
`.claude/rules/subagent-delegation.md` 상단에는 R333 기준 **'기본 메인 직접, 최대 2개로 시작, 실측이 있을 때만 확대'**가 있다. 그런데 같은 파일 아래의 '코드 500줄+ → general-purpose ×N 병렬', '반복 패턴 ×4 → ×4 병렬', 'Explore ×N', '독립 작업 = 3배 속도' 및 '전수조사/설계/검증 단어에 따른 자동 트리거' 설명은 무조건 위임처럼 읽힌다. `.claude/rules/execution-contract.md` §7의 적응형 원칙과도 모순될 수 있다. 실제 dispatcher·Hook·Agent 설정이 어느 정책을 우선 적용하는지 확인 필요.

## P0 — 실제 실행 라우팅·실측 확인
1. 사용자가 일반 기능 구현, UI 디자인, 복잡한 연동, 코드 리뷰, 단순 버그 수정, 대량 독립 파일 변경을 지시할 때 실제 호출 경로가 어떻게 분기되는지 현재 SoT, route_dispatch, Codex/Gemini/Claude subagent, Supervisor 및 Hook 조건을 추적한다.
2. '500줄', '파일 5개', '3+ 파일', '300줄', '전수조사/설계/검증' 등의 고정 규칙이 실제로 불필요한 Agent spawn을 유발하는지 확인. 사용자 명시 'Codex를 써', '병렬로 해' 등 선택도 작업 위험과 비용을 고려해 최대한 충실히 수행.
3. 최근 실측 R333에서 15건 중 서브에이전트 사용 3건은 주요 병목이 아니었고, 읽기 조사 1건은 Opus 상속으로 약 280초/입력 155만 토큰이 소모됨. 이 사실을 유지하되 모든 병렬화가 나쁘다거나 항상 2개만 정답이라고 가정하지 않는다.

## P1 — 상황 적응형 라우팅 정책 통일
- 단순/작은 변경 또는 동일 파일 상태 공유 → 메인 직접 실행.
- 독립 작업이고 결과 결합이 명확하며 측정상 이득 있음 → subagent 병렬, 기본 적은 수부터 시작하여 CPU/RAM·시간·토큰·품질에 따라 조절.
- 깊은 설계·보안·고위험 로직 → 독립 검토를 상황에 맞게 사용; 단어만 보고 위임 강제 금지.
- 디자인 → 실제 화면/기준 캡처, 구현과 검증 역할 분담이 효율적일 때 사용; 디자인 변경의 최종 책임과 캡처 판정은 메인.
- 파일 쓰기 충돌 → 공통 파일 1 writer 원칙, 필요한 경우에만 격리·통합; 무조건 worktree 생성 금지.
- 멀티 AI(Codex/Gemini 등) → 호출 가능 여부·작업 적합성·총 비용·사용자 지시를 기준으로 결정. 토큰 절약만으로 검증 품질을 낮추지 않음.
- 독립 작업 N건이라도 단순히 N배 빨라진다고 표기 금지; 실제 최종 완료 시간에 대기·설명·통합·검증·재작업을 포함.
- 기존 **단일 실행 계약(SoT)**으로 상충하는 과거 숫자/자동 트리거 문구를 정리하되 새 Agent·Hook·Plugin을 추가하지 말 것.

## P2 — 검증과 성과
1. 동일 범위의 대표 작업으로 direct / subagent / multi-AI 선택 결정의 재현 가능한 테스트와 fallback 검증.
2. 모델 호출을 새로 대량 발생시키는 유료 벤치마크는 사용자 별도 승인 없이 금지. 기존 로그/격리 mock으로 검증하고 미측정 구간은 명시.
3. 총 벽시계 시간, 사용 토큰, agent 시작/취합 비용, 충돌/재작업, 최종 검증 품질을 함께 비교. 적응형 선택 근거 기록은 기존 메트릭·원장 재사용.
4. R336의 **위험도별 테스트 선택**과 통합하되 위임 결과도 검증 책임은 메인 Claude. 사용자 요청 전체 완료 ≠ agent 개별 완료.
5. 변경 전 실패/후 통과 테스트, 필요한 범위의 회귀, 핵심 정책 변경 시 전체 회귀, 사실에 기반한 결과 보고.
6. 기존 운영 데이터·원장·디자인 기준선 보존. 완료/승인대기 파일 임의 삭제 금지. 결과는 R337 보고서 하나로 게시하고 정상 검증된 수정만 commit/push.

핵심 목표: **개발·디자인·검증·조사 각각에 적합한 AI/Agent의 최소 충분 조합을 선택하고, 실제 사용자 요청을 더 빨리·정확하게 끝내는 것.**
