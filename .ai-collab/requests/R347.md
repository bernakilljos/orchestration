# R347 — PPTX에 국한하지 말고 모든 문서 산출물의 정확성·전문성·시각품질을 100점 지향으로 개선

## 사용자 핵심 지시
Claude CLI는 사용자가 PPT 하나를 지적했다고 PPT만 고치고 종료하면 안 된다. **PPTX, DOCX, HWPX, XLSX, HTML, PDF 및 실제 지원하는 보고서/설계서/표·다이어그램 형식을 전체 관점에서 검토**하라. 사용자가 말한 40점짜리 문서가 아닌 **검증 가능한 100점 수준을 목표**로 하되 자체 점수 허위 상향, 증거 없는 100점 달성 선언은 금지한다. 앞으로 새로운 출력 형식이 등장해도 등록·발견 가능한 **동적 확장 구조**여야 한다.

기존 R342~R346의 PPT 범용화/하드코딩 금지/외부 레퍼런스 필수/속도·성능·품질 원칙을 모든 산출물에 적용. 1인용 시스템, 사용자 승인된 작업/보호 정책 유지. 운영 소스·고객 민감 문서 원본 무단 외부 업로드 금지. 선행 작업 완료·안정화 전 새로운 대규모 코드개발 착수 금지.

## P0 — 문서 공통 SoT/의미 기반 중간 표현
1. '사용자 요구·근거 소스→사실/추론/가정/미확인 구별→문서 목적/독자/형식 결정→콘텐츠 구조/논증/도식 설계→형식별 렌더→내용·파일·시각·기능 검증'을 하나의 가벼운 공통 계약으로 정의. 무리한 전체 재작성보다 **기존 파이프라인에 최소 변경으로 공통 규칙을 적용**.
2. '특정 제품명/9077/11장/3열 카드/문서당 고정 도식수/고정 레이아웃' 같은 사례별 하드코딩 엄금. 문서 유형별 요구/정보량/독자/다이어그램/문서 크기에 따라 동적으로 결정. 사용자 선택 또는 명시 템플릿은 최우선.
3. 문구의 주어·행동·조건·예외·수치·기간·근거를 명확히. AI 과장 문구, 구현되지 않은 기능 단정, 미검증 수치·관계선 창작 금지. 각 핵심 주장/표 셀/도식 연결선의 추적가능한 출처 매핑과 의미 충돌 탐지.
4. 적절한 그림/차트/ERD/시퀀스/C4/프로세스/네트워크 구조도는 문서 성격과 근거에 따라 선택. 모든 문서에 똑같은 장식적 AI 블록/도형 남발 금지.
5. 새 포맷 지원 시 공통 품질 계약에 **형식별 adapter/validator/renderer**를 연결할 수 있게 하되, 불필요한 새 프레임워크/Agent/Hook/서비스 생성 금지. 현재 존재하는 스킬의 단일 정본과 호환 유지.

## P1 — 형식별 완성도 게이트 (모든 실제 지원 형식)
- **PPTX**: 내용→의미 있는 아키텍처/프로세스 다이어그램, 화살표 정확성, 읽기 쉬운 제목/본문, 렌더된 전체 슬라이드 시각 검토, 편집 가능 구조, 발표용 정보 밀도.
- **DOCX**: 제목·헤딩·목차·페이지/구역·표/그림/캡션·참고문헌·번호/각주/교차참조, 긴 표의 분할/미망·고아행/페이지 경계, 회사 양식/인쇄 레이아웃, 렌더된 페이지 실제 확인.
- **HWPX**: 한컴 OWPML 표준과 섹션/스타일/표/그림/페이지·한글 조판 및 한컴 실제 열기 호환성, 문서 구조 검증. 지원 도구가 없어 실렌더 불가한 부분은 '미검증'으로 보고, XML만 맞다고 100점 주장 금지.
- **XLSX**: 수식/결과 캐시·재계산 동작, 참조 무결성, 데이터형·날짜·통화/단위·조건부 서식·시트 링크, 샘플 값 수작업 역검증, 필터/고정틀/인쇄영역, 차트/표 편집 가능성, 수식 조작 위험 및 사용자 데이터 보존.
- **HTML**: 시맨틱 구조, CSS 반응형/인쇄 스타일, 모바일/데스크톱/긴 텍스트·표, 키보드 접근/대비/WCAG 적용 가능성, 링크·이미지·스크립트 안전성, 브라우저 실제 렌더 확인.
- **PDF**: 페이지/표/이미지/폰트 포함·텍스트 검색 가능 여부·한글 깨짐·인쇄 정확도, 의미 구조·접근성, 요청된 PDF/A·PDF/UA 준수 여부, 전 페이지 시각 검증.
- **기타**: Markdown, diagrams, CSV, ODT/ODS, 코드 생성 보고서 등 발견되는 지원 범위별 출력 의미·파일 적합성·편집성·사용성을 동일하게 검토. 지원되지 않는 포맷을 억지로 '구현됨'이라고 하지 말 것.

## P2 — 독립 품질 평가, 실제 근거, 과적합 차단
- 공통 평가 100점 기준(형식·독자별 가중치 동적): 사실 정확성·출처 추적, 내용 누락 방지, 목적 적합성, 구조/도식·표의 의미 정확성, 시각 가독성, 포맷 기능성/호환, 재사용·편집성. 현재 PPT 40~45점은 **그 자료에 대한 평가**이지 다른 형식의 실제 점수가 아님. 실제 생성 샘플 없이 다른 포맷 40점으로 추측 금지.
- 형식별 서로 다른 주제의 **고객 정보 없는 대표 샘플** 최소 1개(가능하면 각 2개)를 생성/검증. 포트/제목/데이터/내용 길이/표·이미지 수를 달리하여 고정 패턴·하드코딩 누출 탐지. 출력 생성→재열기→스키마/내용/수식/경로 확인→실제 렌더/시각 검사까지 진행. 판독 불가능한 형식은 정직한 제한 보고.
- 기술 주장·표/도식 값이 원본과 다르면 fail; 원본과 다른 숫자/사업 내용 삽입 금지. 출처를 추적하기 어려우면 '미확인'으로 분류. 점수 100 자체를 목표로 품질 게이트 완화 금지.
- **성능**: 단순 문서에 매번 여러 모델/전체 프로그램 호출하지 말고 필요한 검사만 적응형. 생성시간 p50/p90, 렌더·검증 시간, 메모리/토큰·비용, 재생성/수정 횟수, 품질 결함 비교. 속도·성능·품질을 모두 입증.
- 외부 인터넷 검색은 실질 자료/포맷·최신 기술 지식이 유용할 때 필요하며, 고객/회사 기밀·문서 전문을 허가 없이 외부 전송하지 말 것. 버전/근거 URL·접근 날짜 남기기.
