1. `.claude/scripts/statusline_context.py`, `.claude/scripts/design-gate.py`, `.claude/design-baseline/statusline.json`, 원천 상태 파일·메트릭 산출 스크립트·캐시를 역추적해 **표시 항목마다 원천 파일/쿼리/기준 시간/TTL/오류 시 폴백** 표를 작성. 운영 데이터는 읽기 전용 확인.
2. `R338 5/6(83%) 전파 차단`과 `현재 R338 검증중`이 한 시점에 의미상 일관되는지 검증. '5/6'은 개발 파이프라인 6단계인지 'R338의 6개 품질 영역'인지 반드시 구분 표시. 다른 의미를 사용자가 혼동하지 않도록 정확하고 짧은 표현으로 개선.
3. `READY 60/100 · 검증 ✅ · 배포 ✅ · 품질 C`는 각각 별개의 판정인지 근거·갱신 시점·합산 규칙 확인. '검증 OK'가 전체 요구사항 완료/READY 고득점과 동의어가 아니므로 모순처럼 보이는 경우 명확히 설명. 임의 가중치 재설계 금지.

## P1 — 시각 품질·가독성 (현행 유지·최소 개선)
1. 실제 VS Code의 사용자가 승인한 상태줄 캡처로만 픽셀/수직축 판정; 터미널의 한글·이모지 wcwidth/Variation Selector, 폰트 설정, ANSI, `│` 위치를 확인. 임시 텍스트 맞춤만으로 PASS 금지.
2. 기존 10줄/정보 구조를 우선 유지. 긴 오른쪽 내용에 의한 잘림, 너비별 2열↔1열, 높이 10줄 기준선과 design-gate의 '11줄' 설명 차이를 실제 코드·캡처로 확인하고 필요한 부분만 수정.
3. 긴 메트릭은 핵심 변화/문제부터 읽히게 개선할 수 있으나 사용자 동의 없이 메뉴·지표를 숨기거나 제거하지 말 것. 반짝임/불필요한 색상/이모지 추가 금지.
4. Golden baseline의 무단 변경 금지; 변경 필요하면 사용자 실제 의도를 먼저 확인. 터미널/화면 캡처는 평상시에 실행하지 말고 필요한 한정된 경우에만, 사용자 허가한 대상에 대해서만.

## P2 — 지표 렌더링 성능·안전한 회귀
1. 상태줄 갱신 1회 wall time 및 CPU/RAM·파일 읽기·git/subprocess·JSON 파싱 호출 횟수/중복 캐시를 계측하고 체감 지연을 줄일 방법을 찾아라. 최신성 훼손·과도한 상주 측정 금지.
2. 상태줄 표시는 실제 사용자 명령/git push/승인된 캡처를 방해하지 않는 읽기 전용 경로를 원칙으로 하고, 임시 파일의 중복 생성이 있으면 보존 필요성·비용부터 검토.
3. 정상/데이터 누락/캐시 오래됨/카운터 폭주/원장 손상/긴 텍스트/좁은 터미널/이모지 혼합 입력을 격리 테스트. 필요한 변경 범위 테스트 및 위험 높은 공통 코드 변경 시 전체 회귀를 적절히 선택(R336).
4. 전후 측정, 숫자 근거, 변경 내용과 사용자에게 실제 보이는 차이를 보고. 불확실하면 PASS가 아니라 미검증을 기록. 데이터 품질을 떨어뜨리거나 단순 UI 장식으로 실질 정보를 없애지 말 것.
