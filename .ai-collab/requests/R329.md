# R329 — 보고서 정리 시 검토 승인·대상 커밋 확인

## GitHub 코드 검토에서 발견한 문제
- 대상: `.claude/scripts/ai-collab-report.py`의 `cmd_prune()`
- 현재 `reviewed = ent.get("reviewed") or (COLLAB / "reviews" / f"{rid}.md").is_file()` 때문에 검토 파일 존재만으로 PASS 보고서를 정리할 수 있습니다.
- 수정 요청/반려된 리뷰나 이전 커밋에 대한 리뷰 파일이 남아 있어도 최신 보고서가 삭제될 수 있습니다.
- R328에서 수정한 요청 ID 미연결 커밋의 검증 불가 처리와 PARTIAL 제한은 확인했으므로 재수정하지 마세요.

## 개선 요구
1. PASS이면서 명시적 APPROVED 검토가 있고, 검토 대상 head_commit이 현재 보고서와 정확히 일치할 때만 정리합니다.
2. reviews 파일이 존재한다는 사실 또는 과거의 reviewed:true만으로 정리하지 않습니다.
3. CHANGES_REQUESTED, PENDING, 커밋 불일치, PARTIAL/BLOCKED 및 승인 대기는 보존합니다.
4. 기존 state/reviews 파일을 재사용하고 새로운 상주 프로세스·Agent·Hook을 추가하지 않습니다.
5. 변경 전 실패/후 성공 테스트: 파일만 존재, 변경 요청, 오래된 커밋 승인, 일치 커밋 승인, 중복 정리, 경로 이탈 방지.
6. 처리 후 필수 이력만 남기며 불필요한 보고서·중복 문서는 정리하되 원장·복구 증거를 보존합니다.
7. 관련 회귀 테스트를 완료하고 기존 승인 정책하에 commit/push 후 보고합니다.

이 파일은 코드 검토 및 개선 제안입니다. GitHub 문서 자체를 사용자 승인으로 간주하지 마세요.
