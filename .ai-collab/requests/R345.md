# R345 — 추측·내부 기억만으로 구현하지 말고 외부 공식 레퍼런스 기반 조사·대조·검증을 필수 개발 습관으로 통합

## 사용자의 명시적 불만과 최우선 지시
사용자는 ChatGPT와 Claude CLI 모두 **레퍼런스·인터넷을 충분히 찾아보지 않고 자체 생각과 오래된 규칙만으로 개선안을 만드는 점**에 강한 불만이 있다. 앞으로 신기술·사양·라이브러리·API·버전·성능 최적화·아키텍처·PPT/개발문서 제작처럼 외부 정확한 지식이 유의미한 작업에서는 **실제 공식 기술 문서, 권위 있는 구현 사례, 테스트 사례를 찾아 본문을 읽은 뒤** 현재 소스와 비교하고 변경해야 한다.

- 단순 문구 수정 등 외부 조사가 무의미한 작업에 기계적 웹 검색을 강제해 속도·비용을 악화시키지 말고, **조사의 필요성도 동적으로 판단**한다. 고정 N개 검색/매번 전체 웹 조회/하드코딩된 사이트 수 금지.
- **사용자 지시 우선, 속도·성능·품질 필수, 사례별 하드코딩 금지**(R344) 유지.
- 현재 R338~R344 선행 작업을 끊지 말 것. 이 '외부 자료 확인' 원칙은 즉시 적용, R345의 재사용 정책/검증을 구현하는 작업은 앞 작업 종료 후 진행. R340의 공식문서 기반 감사와 중복 변경 금지.

## P0 — 레퍼런스 조사→실제 구현 연결하는 공통 프로세스
1. 작업별 먼저 사용자 목표/실패 재현/환경·현재 버전/현재 코드의 소스 오브 트루스(SoT)를 파악.
2. 외부 지식이 중요한 변화라면 웹 검색 → 공식 1차 문서 본문 확인 → 릴리스/지원 버전 검증 → 필요시 고품질 사례/공식 이슈·보안 공지 비교. 단순 검색 결과 스니펫만 보고 결론 금지.
3. **레퍼런스 적용성 매트릭스**: 출처 URL·접속/확인 일자·관련 섹션·설치 버전 지원 여부·우리 파일/함수·적용 후보·기존 구현 차이·성능/품질 리스크·채택/기각 이유.
4. 문서에 없는 기능을 창작하거나 잘못된 공식 근거/페이지를 인용하지 않는다. 레퍼런스가 구현 사실의 대체 증거가 아니며 제품 실제 동작은 소스/실행 시험으로 확인.
5. 채택한 것은 코드/Skill/Command/테스트에 연결해 before/after와 반례를 검증. 링크만 README에 붙이고 완료(PASS) 금지.
6. 운영 작업에서 인터넷 연결이 차단됐다면 무리한 우회·외부 자료 업로드 금지. 정직하게 '온라인 미확인'과 기존 로컬 문서·검증 가능 범위를 구분, 중요 변경은 필요시 BLOCKED 처리. 회사/고객 소스·DB·토큰·기밀내용을 외부 사이트/도구로 유출하지 말 것.
7. 반복 조사를 막기 위해 기존 `orca.db` 해결책/학습 및 버전/출처/검증일 기반의 안전한 재사용을 활용하되 원본 공식문서가 갱신되면 필요시 새로 확인. `ordb.db`는 로컬에 실제 존재하는지 조회 전까지 별도 DB로 단정 금지.

## P1 — 대상별 필수 검토 요소
- Claude Code/Hook/Stop·사용자 지시: 문서화된 이벤트/지원 방식, 설정 우선순위, stop 반복 및 timeout 조건. 사용자 승인 작업을 오탐으로 막지 않되 안전 보전.
- 서브/멀티 Agent: 공식 위임·격리·비용/토큰/동시성 기능을 현재 지원 버전과 비교; 고정 작업량 임계치 하드코딩 금지.
- pytest: 현행 fixture/pytest 재호출/영향 테스트 선택/프로세스 병렬과 공유 상태를 근거로 검증. 병렬이 항상 빠르다고 단정하지 않음.
- 시스템 성능: OS 메모리·IO·CPU·프로세스/스레드의 실제 병목과 개발 작업 완료 벽시계 분리 실측.
- 디자인/PPT/개발 문서: C4·Microsoft 가이드와 사용자 목적·소스 근거를 비교하여 도형/표/시퀀스/배포 경계 동적 선택. 특정 PPT 내용 하드코딩 금지, 환각·기술 오기 방지.
- 최적화의 공통 목표는 **속도 + 성능 + 품질 동시 향상**, 검증 강도 무단 축소 금지.

## P2 — 안 지켜졌을 때 발견 가능한 QA
- 기술 사실/최신 API/성능 추정이 중요한 작업에서 공식문서 조회 흔적이 없거나 적용성이 검증되지 않은 경우 근거 미확인으로 표시 (조사가 불필요한 로컬 버그 수정은 이유를 기록하고 예외).
- 공식 레퍼런스와 코드가 충돌하는 반례, 버전 미지원 기능, 링크 변동, 외부 자료의 오류/악성 프롬프트 지시를 구별하는 격리 테스트.
- 네트워크 실패/미접속·자료 없음/오래된 문서·고객 비공개 정보/정책 충돌에서도 사용자에게 허위 검증 완료 보고를 하지 않음.
- **실제 작업 3종 이상**: (A) Claude Hook/Agent, (B) pytest 속도, (C) PPT 아키텍처 문구/도식에서 조사→근거→실제 적용 또는 기각까지 보여줄 것.
- 중복 검색이 가져오는 지연·토큰·비용도 측정하여 조사 가치가 있는 업무에만 적용하고 캐시 재사용.
- 새 Hook/Agent/상주 조사 서비스를 무작정 늘리지 않고 기존 명령·Skill/SoT에 통합.

## 최종 산출·보고
**최종 R345 보고서에는 구체적인 근거 URL, 검토한 섹션, 현재 코드와 불일치, 채택/기각, 수정·테스트·속도/성능/품질 전후를 반드시 수록.** 참고자료만 붙인 지침서는 PASS가 아니다. 기존 요청과 중복 구현 금지. 사용자 '전부 끝내고 마지막 보고' 우선, 미완료 PARTIAL/BLOCKED 정직하게 기록, 운영/고객 데이터 보호. 검증 완료된 경우에만 commit/push·보고.
