# R335 — 사용자의 명시적 최종 완료·보고 지시가 Hook 정책보다 우선하도록 실행 흐름 바로잡기

## 실행 시점
- 현재 R334가 아직 보고되지 않았다. **R334 진행을 끊지 말고 먼저 끝낸 뒤** 이 지시를 처리할 것.
- R334가 검증상 PARTIAL/BLOCKED면 이유·미완료를 보존하고, 선행 작업의 무한 대기나 임의 PASS 전환 없이 실제 실행 가능한 후속 작업으로 연결.
- 본 문서는 다음 작업 요청이며, 사용자 승인 필요한 민감 작업의 권한을 대체하지 않는다.

## 사용자가 겪는 실제 문제 (최우선)
사용자는 Claude CLI에 **'전체 작업을 모두 끝내고 테스트·검증까지 완료한 다음 마지막에 한 번만 보고하라'**고 분명히 지시한다. 그런데 하위 작업 하나를 끝내자마자 보고하고 멈추는 일이 반복된다. 무조건 모든 작업에 중간보고를 금지하라는 요구가 **아니다**. **사용자 지시가 있을 때 그 의도가 일반 Hook·기본 보고 정책보다 우선**해야 한다. 사용자가 '하나씩 보고', '중간마다 확인'을 지시하면 그대로 따르며, 별도 지시가 없으면 기존 기본 동작을 유지한다.

## P0 — 재현 원인 추적
1. 실제 사용자 지시문과 Request Ledger 생성 항목, 원장·하위 item 상태, Stop payload, Stop Hook 결과, Supervisor goal/next-actions 흐름을 비교하여 '전체 완료 요구 → 하나만 완료 → 최종처럼 보고/Stop' 현상을 재현. 근거 없는 추측·완료 주장 금지.
2. `.claude/rules/execution-contract.md`, `.claude/scripts/request-ledger.py`, `.claude/hooks/stop-request-ledger-gate.sh`, `.claude/hooks/stop-active-goals-resume.sh`, 관련 Stop hooks/상태머신의 실제 우선순위·예외를 추적.
3. 특히 원장 부재 시 Stop 허용, PARTIAL/BLOCKED 종료 예외, 하나의 상위 요청 아래 하위 항목 누락·NA 조기 처리, '미완료 목록만 기록 후 종료' 경로를 검증. Stop을 차단하는 데만 집중하지 말고 **다음 실행 가능한 작업을 실제로 이어서 진행할 수 있는가** 검증.

## P1 — 사용자 지시 중심의 완료 계약
1. 원문에 명시된 작업 범위·보고 시점('전부 완료 뒤 1회' / '작업별 보고' / 기본)을 원장/상태에 기록하고 사용자 **최신 명시 지시**로만 변경한다. Hook이 임의로 범위 또는 보고 시점을 축소·확대하지 못하게 한다.
2. 사용자 '전부 끝내고 보고' 지시가 있으면 하위 1/N 완료는 진행 상태일 뿐 최종 완료로 처리하지 않는다. 실행 가능한 잔여 항목을 자동으로 순차 진행(독립 작업은 충돌 검증 후 병렬), 완료+검증+요구사항 일치가 확인된 뒤 최종 1회 보고.
3. 사용자가 '중간보고'를 지시하거나 강제 중단/방향 변경하면 최신 사용자 지시를 따르고 예전 계약을 무리하게 유지하지 않는다.
4. 진행 불가한 승인·보안·데이터 보호·비용·실제 환경 오류·자원 한계는 정직하게 BLOCKED/PARTIAL로 중단 사유를 알린다. **미완료를 PASS로 바꾸거나, Stop Hook 무한 재귀/반복으로 모델 비용을 소모하지 않는다.**
5. 일반적으로 승인된 정상 git push, 사용자가 승인한 화면 캡처 등을 과도한 Hook 오탐으로 막지 않되, 기존 민감 작업 보호·원장·복구 증거 유지.
6. 새 Agent/Hook/상주 프로세스를 추가하지 않고 기존 원장·Stop Hook·Supervisor 로직 최소 수정. 정규 작업 속도에 유의미한 추가 지연을 만들지 않는다.

## P2 — 검증 가능한 테스트
수정 전 실패→수정 후 성공을 보이는 실제 Stop·원장·Supervisor 통합 테스트:
- 사용자 '3개 전부 끝내고 마지막에 보고': 첫 번째만 PASS이면 최종 보고/정상 Stop 금지, 2·3번 수행 후 종합 검증·최종 보고.
- 한 메시지 안 하위 요구 5개 중 하나 미완료: 전체 PASS 거부.
- 사용자 '하나씩 보고' 또는 중간 승인 지시: 적절한 중간 보고 허용.
- 별도 보고 방식 지시 없음: 기존 기본 동작 회귀 없음.
- 최신 사용자가 중단/범위 변경: 원장을 정직하게 조정하고 새로운 지시 이행.
- 승인 대기·실패·리소스 제한: BLOCKED/PARTIAL을 사실대로 남기고 무한 반복하지 않음.
- Stop Hook이 차단했더라도 실제 후속 작업이 실행되는지 확인. 가짜 테스트/문구 PASS만으로 대체 금지.

- 실제 전체 완료 확인되지 않으면 PASS 금지. 안전한 조건에 한해 commit/push, 선행 R334 및 사용자 현재 작업 방해 금지.
- 완료된 중복 파일은 승인·head 일치 확인 후에만 정리. 원장·복구 증거·진행 중/승인 대기 자료 보존.

핵심 성공 조건: **사용자가 '모두 끝내고 마지막에 보고해'라고 하면, Claude CLI는 1개를 끝냈다는 이유로 최종 보고하고 멈추지 않는다. 사용자가 그렇게 지시하지 않았다면 일반적인 보고와 진행 판단은 기존대로 한다.**
