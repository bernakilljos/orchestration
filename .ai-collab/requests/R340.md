# R340 — 선행 작업 완료 후 공식 레퍼런스 기반 전면 성능 재감사·숨은 최적화

## 사용자 요구와 순서
R334~R339 모두 먼저 완료·검증하고, R338의 **아키텍처·검증·사용자 지시 준수·성능·디자인 다섯 영역을 우선 개선하고 마지막에 자동화·자율 실행까지 개선**한다는 순서를 유지하라. 그 뒤에 R340을 시작한다. 1인 전용 시스템이다. 사용자가 '전부 끝내고 검증 후 마지막에 한 번 보고'라고 지시했다면 일부만 완료하고 종료하지 말 것. 단 실제 승인/보안/비용/장애로 불가능하면 정확히 PARTIAL/BLOCKED로 기록하며 무한 재시도 금지.

이미 발견한 문제만 손보지 말고 **공식 문서와 현재 설치 버전/소스코드를 대조하여 우리가 아직 모르는 속도 개선 기술을 발굴·실측·적용**하라.

## P0 — 개발의 스레드/병렬/가상메모리 아이디어도 검증
1. **동시성:** Claude Code의 직접 실행, subagents foreground/background, 별도 세션, Agent Teams(설치 버전에서 지원될 경우), worktree 분리, Python async/ThreadPoolExecutor/ProcessPoolExecutor, pytest-xdist(프로세스 기반) 중 어느 수준이 실제 병목에 효과적인지 분석. 이들 개념을 서로 동일한 '스레드'로 오인하지 말 것.
2. **작업 분류:** I/O 대기(원격 조회/도구 호출/테스트 결과)에는 제한된 비동기·스레드 처리 가능성, CPU-bound 작업에는 안전한 프로세스 병렬 또는 라이브러리 활용 가능성을 따로 검증. 동일 파일/SQLite/원장 동시 쓰기와 Hook·사용자 승인 경합을 방지. 멀티에이전트 수는 무조건 늘리지 말고 토큰·시간·품질 비교.
3. **가상메모리:** Windows 가상메모리는 컨텍스트 창/LLM 토큰 메모리를 늘리는 기능이 아님. 실제 RAM, commit charge/limit, 페이지 파일, working set, hard faults, 디스크 I/O와 OOM 징후를 구분. 페이지파일 크기 조절/Defender 비활성화/타 프로세스 종료 등 시스템 변경은 명시 승인 없이 하지 말 것. '가상메모리를 늘리면 모델이 빨라진다' 같은 근거 없는 주장 금지.
4. **메모리 게이트:** R339에서 분석하는 300초 _wait_memory_for_heavy 대기, 파이썬 subprocess 재기동, 중복 테스트 격리/컴파일 등과 혼동하지 않고 호출 경로별 실제 지연 분리.
5. **컨텍스트 비용:** CLAUDE.md/Rules/Skills/Plugins/MCP의 자동 로딩 중복, 매번 불필요한 전체 파일 읽기/출력, 세션 compaction/cache의 실효성과 재검증 부담 계측. 기존 안전·이력 보존.
6. **Stop Hook·Supervisor:** 사용자 명시 '전부 끝내고 보고' 조건을 Hook이 무시하는지, 매턴 반복 조회/Stop 오탐/재실행/불필요한 상태 저장 확인.
7. **UI/체감:** VS Code 터미널 렌더링, statusline 업데이트, 한글/이모지 폭, 대시보드의 응답성은 실제 승인된 화면 캡처·계측으로 검증. 임의 ANSI 고정열 복원 금지.
8. **테스트:** R334/336/339 결과와 겹치지 않는 추가 개선. 테스트 삭제·skip·xfail·약한 mock 대체 없이 유형에 맞는 회귀 검증과 높은 위험의 전체 회귀를 보존.

## 검증·성과
- **재현 가능한 프로파일**: 사용자 실제 개발 작업의 end-to-end 벽시계(요구 등록→검증된 최종 완료), 각 단계 latency p50/p90, 요청당 에이전트·토큰·메모리·CPU·disk, 오류/재작업, 테스트 결과. ChatGPT 협업을 위한 임시 5분 cron 397회는 평시 개발 병목 수치에서 제외.
- **후보 비교**: 각 최적화 아이디어에 공식 근거, 현재 설치 버전 지원 여부, 변경 전후 측정, 위험, 효과, 채택/기각 사유를 남긴다. 가설만으로 수치 지어내지 않음.
- **구현**: 가장 효과 큰 저위험 개선부터 기존 코드에 최소 수정. 새 Hook/Agent/상주 서비스/다중 사용자 구조 추가 금지. 고비용 유료 모델 벤치마크나 Windows 시스템 설정 변경은 사용자 승인 없이는 금지.
- **증거**: 변경 전 실패·후 성공, 관련 회귀, 필요시 전체 회귀, 중복·승인 게이트 테스트. 실제 개선율과 품질 모두 확인. 개선이 없거나 회귀하면 원복.
- **정리**: 운영 DB/원장·복구·감사 증거와 진행 중/승인 대기 보존. 이미 승인·검증된 완료 임시 파일만 안전하게 정리. 결과는 R340 보고서 하나로 commit/push하고, 미검증을 PASS로 기록하지 않는다.
