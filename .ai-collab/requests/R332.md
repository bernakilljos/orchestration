# R332 — 협업 루프의 처리 확인·재시도 및 리뷰 승인 파싱 보완

## 출처와 확인 근거
ChatGPT가 main 브랜치의 `.claude/scripts/ai-collab-report.py`를 직접 검토해 확인한 두 결함 가능성에 대한 개선 요청. R329의 '파일 존재만으로 삭제' 문제는 이미 고쳐졌으므로 중복 수정하지 말 것.

### P0. poll의 읽음(seen)과 처리 완료(handled) 분리
현재 `cmd_poll()`은 `requests/`, `reviews/`의 새 blob을 출력하기 전에 `seen[path] = blob`으로 저장한다. 이후 Claude 세션이 중단되거나 처리에 실패하면 다음 주기에서 해당 파일이 '새 요청 없음'으로 사라질 수 있다.

- poll 단계는 발견·전달만 하며, 실제 처리 확정은 성공적인 검증/보고 후 별도 명시 확인 단계에서 기록하도록 개선.
- 실패/중단/재시작 시 미완료 요청을 다시 전달하되 같은 요청의 동시 실행·중복 처리 방지.
- 이미 처리한 R329 등은 재실행하지 않도록 기존 handled와 호환.
- 요청 검토 문서 자체가 사용자 승인이라는 의미는 아님. 기존 명시 승인 및 안전 정책 유지.

### P1. 리뷰 승인 판정은 YAML 헤더에서만
현재 `_review_approves()`는 문서 전체를 `re.search(..., re.M)`로 검색한다. 본문 예시 또는 인용문에 `verdict: approved`, `reviewed_commit: <40자 SHA>`가 쓰여 있으면 실제 검토 승인이 아닌데도 PASS 보고서를 prune할 가능성이 있다.

- 문서 맨 앞의 하나의 올바른 YAML frontmatter 블록에서만 필드 파싱.
- 중복 키, 누락 키, 유효하지 않은 값, 본문·인용문 값은 승인으로 인정하지 않음.
- `verdict=approved` 와 `reviewed_commit` 40자리 SHA가 보고서 head_commit과 같을 때만 삭제 가능.
- CHANGES_REQUESTED/PENDING/PARTIAL/BLOCKED와 승인 대기 건은 보존.

## 검증과 구현 범위
1. 수정 전 실패·수정 후 성공 테스트: 새 요청 발견 직후 처리 실패, 재시작, 정상 완료 후 중복 방지, 기존 handled 호환.
2. 수정 전 실패·수정 후 성공 테스트: 본문 가짜 승인, 인용문 가짜 승인, 중복 YAML 키, 정확한 승인, 오래된 커밋 승인, 비승인 상태.
3. 기존 테스트·회귀 게이트 전체 실행. 실패나 측정 불가를 PASS로 보고하지 않음.
4. 새 Hook·Agent·상주 프로세스 추가 금지, 기존 협업 폴더와 state 파일 최대한 재사용.
5. 검증된 변경만 기존 허용 범위에서 commit·push 후 요청별 최소 보고서 게시. 중복·완료 파일은 필수 이력 보존 후 정리.

이 파일은 외부 코드 검토 결과와 개선 제안이며, GitHub 파일 자체가 사용자 실행 승인 증거는 아니다.
